# Резервные копии Task DB

Инструмент `poise backup` создаёт, показывает и восстанавливает резервные копии SQLite-базы задач AI poise. Он работает только с настроенным файлом Task DB. Файлы артефактов самостоятельных Task в `standalone/`, Task-участников в `sprint/<sprint-id>/task/` и артефакты Sprint в `sprint/` в резервную копию не входят.

Для полного проекта нужна отдельная [полная копия всех хранилищ и материалов](architecture/storage-lifecycle.md#резервное-копирование-и-восстановление); эта команда не резервирует Requirements DB и Git.

## Обязательное условие

Команды `create` и `restore` запускает один оператор только тогда, когда ни один agent, другой process или экземпляр AI poise не пишет в Task DB. Онлайн-резервирование и координация конкурентных операций не входят в контракт инструмента.

Во всех примерах `PROJECT_JSON` — путь к выбранной конфигурации проекта.

## Расположение копий

Путь к рабочей базе берётся из проектной конфигурации. Копии всегда находятся в каталоге `backups/` рядом с настроенным файлом базы данных. Отдельной настройки пути к резервным копиям нет.

Инструмент не создаёт реестр метаданных или checksum-файлы. Достаточным идентификатором служит описательное имя файла копии.

## Список

```bash
poise backup list --config PROJECT_JSON
```

Команда возвращает JSON с массивом `backups`. Для каждого обычного файла выдаются только поля `name` и `created_at`; элементы отсортированы по имени. `created_at` — время файловой системы в UTC, полученное из `ctime`. В Linux `ctime` означает время последнего изменения метаданных inode, а не переносимую дату рождения файла.

Пример:

```json
{
  "backups": [
    {
      "name": "tasks-backup-20260912T123456123456Z.sqlite",
      "created_at": "2026-09-12T12:34:56.123456+00:00"
    }
  ]
}
```

Внутренние временные файлы `.pending`, символические ссылки и каталоги в список не попадают.

## Создание

```bash
poise backup create --config PROJECT_JSON
```

Инструмент копирует настроенную Task DB средствами SQLite во временный файл, выполняет `PRAGMA integrity_check`, синхронизирует файл и атомарно публикует его под сгенерированным именем. При совпадении имени существующая копия не перезаписывается.

Успешный результат содержит только имя, признак успеха и размеры рабочей базы и копии в байтах:

```json
{
  "success": true,
  "name": "tasks-backup-20260912T123456123456Z.sqlite",
  "live_size_bytes": 131072,
  "backup_size_bytes": 131072
}
```

Если синхронизация каталога завершилась ошибкой уже после публикации, сообщение прямо указывает, что файл создан, но его устойчивость к аварийному завершению системы не подтверждена. До повторного запуска проверьте его через `poise backup list` и выполните SQLite `PRAGMA integrity_check`.

## Восстановление

```bash
poise backup restore --config PROJECT_JSON tasks-backup-20260912T123456123456Z.sqlite
```

Имя передаётся как один точный компонент файла: пути, `.` и `..`, символические ссылки и внутренние `.pending`-имена отклоняются. Перед изменением рабочей базы выбранная копия проходит `PRAGMA integrity_check`. Затем инструмент создаёт и проверяет соседний временный файл и атомарно заменяет настроенную Task DB.

Успешный результат:

```json
{
  "success": true,
  "name": "tasks-backup-20260912T123456123456Z.sqlite"
}
```

Отсутствующая, нечитаемая или повреждённая копия отклоняется до замены рабочей базы. Если синхронизация каталога завершилась ошибкой после замены, не запускайте writers и проверьте рабочую базу командой SQLite `PRAGMA integrity_check` до повторной попытки.

## Справка

```bash
poise backup help
```

Справка кратко перечисляет `list`, `create` и `restore` и напоминает об обязательном отсутствии записывающих agent и process.

## Резервная копия перед миграцией process snapshot

Операция `task-process-migrate` принимает точное `backup_name` ранее созданной публичной
копии. Создайте её через `poise backup create --config PROJECT_JSON`, пока ни один другой
writer не работает с Task DB, и не удаляйте после миграции. Операция до первой записи и
повторно внутри своей транзакции требует, чтобы полное состояние рабочей базы совпадало с
этой копией. Пошаговый операторский контракт приведён в
[руководстве по миграции](task-process-snapshot-migration.md).
