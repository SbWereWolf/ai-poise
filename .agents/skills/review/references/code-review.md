# Evidence-based finding procedure

Apply the canonical [finding criterion](../../../../docs/workflows/evidence-based-review.md#что-считать-находкой) to the exact result revision. This reference does not define a lifecycle or change the executor/reviewer roles.

## Establish an obligation

Locate the current user requirement, Task contract, API/schema or applicable canonical rule. A historical proposal, another project's architecture or reviewer preference is not a current obligation. Identify the producer stage and the later gate that should observe its result.

## Reproduce the discrepancy

Name the condition and observable consequence, inspected revision and smallest reproducer. Read real owners, callers, consumers and direct effects. Batch independent managed reads, then expand through demonstrated dependencies without expanding write scope. Distinguish runtime/contract defects, executor defects, reviewer mistakes, protective rejection and unresolved causes from facts.

## Inspect proof quality

Check that test expectations are independent, allowlists describe the subject rather than silence a checker, negative cases are meaningful, and evidence belongs to the inspected tree. Check source/build identity only where material. Use the project's exact targeted commands and maintained fast smoke; neither smoke alone nor a full suite substitutes for the affected contract.

## State a verifiable correction

A finding contains the obligation, condition/consequence, evidence and correction criterion. Preserve existing finding IDs across remediation. Supply new genuine findings only through the current batch API shape. Do not demand an implementation preference where several solutions satisfy the contract.

## Deliver the review

Check completeness against the agreed scope, actual diff, data flow, ownership/reuse, tests, documentation and early artifacts. Challenge false positives in your own findings. Store one batch and its limitations; a bounded no-finding result is valid without synthetic findings or skipped-role ceremonies. Remain read-only and hand off through the existing public owner.
