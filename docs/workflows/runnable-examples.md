# Автономные примеры AI poise

Обновлено: **2026-09-17**.

## Запуск в новом каталоге

Примеры используют текущий исходный код AI poise и Python 3.13. Они создают только
новый указанный каталог с учебным приложением, проектной конфигурацией, Git и SQLite.
Существующий каталог не перезаписывается. Из корня репозитория:

```bash
PYTHONPATH="$PWD/src" python -B examples/demo.py --directory /absolute/path/to/new-demo
PYTHONPATH="$PWD/src" python -B examples/hooks_demo.py --directory /absolute/path/to/new-hook-demo
```

Каждый сценарий проводит одну учебную задачу через публичный API: регрессионный
тест действительно падает до изменения `double`, затем проходит после исправления.
Итоговые `demo-report.json` и `hooks-demo-report.json` сохраняются в выбранных
каталогах. Сообщения и доклады этапов — явно обозначенные fixtures, не независимый
осмотр проекта и не пользовательская приёмка реального результата.

## Явная конфигурация и изоляция

Примеры задают `paths.standalone_tasks`, отдельное хранилище телеметрии, окружение
проверок и `git.push_required=false`. Они не создают remote и не вызывают push;
проверенный результат остаётся на учебной Task-ветке, исходная `main` не меняется.
Это не меняет правила публикации или интеграции настоящих проектов.

Обычный пример очищает унаследованные native-переменные и использует собственный
постоянный `POISE_CALLER_BINDING` внутри нового каталога. Hook-пример передаёт
согласованную синтетическую native-идентичность только своим дочерним процессам.
Переменные реальной сессии пользователя не переписываются. Hook JSON, сообщения
и события воспроизводятся локально через созданный launcher: это проверка
протокола, а не запуск живого Codex/IDE. Настройки доверия Codex не изменяются.

## Проверка примеров

Адресные регрессии находятся в `tests/hook_transport/test_example_contract.py`
и `tests/hook_transport/test_demo.py`. Результат оценивается по завершению процесса,
сохранённому отчёту, реальному RED/GREEN и отсутствию удалённой публикации.
Незавершённый запуск с истёкшим внешним лимитом не считается ни успешной проверкой,
ни доказанным зависанием; сначала проверяются сохранённый exit code и subprocess.
