## Что добавлено в поведение

**C017:** существующий `AiPoiseTestPackages` сопоставляет конкретные diff-пути со всеми
категориями `source/tests/support/fixtures`, включая новые и удалённые файлы.
Переименование передаётся парой старого/нового пути. К прямым владельцам добавляется
ровно один шаг явно объявленных integration boundaries; весь граф не подтягивается.
Обязательные методы Task сохраняются, неизвестные входы дают исправляемую диагностику,
а не пропуск проверки или full-suite. Используются прежние runner и cache.
[Точный контракт](../../configuration/development-routing.md#выбор-проверок-по-входам-тестовых-пакетов).

**C029.4:** зарегистрированная проверка собственной Python-архитектуры AI-poise
вызывается до авторской сдачи. Известное нарушение или неокончательная проверка
не меняют Task, claim, версию, стадию и историю; исправление принимается повтором
в той же задаче. Работа с выделенной папкой и без worktree проверена отдельно.
Operational policy остаётся у выбранной конфигурации работающего Poise, а не
подменяется файлом из проверяемой копии.
[Точный контракт](../../workflows/architecture-boundaries.md#проверка-архитектуры-перед-авторской-сдачей).

Семь остальных задач используют уже поставленные F1/F2 owners. Нет второго router,
runner, универсальной схемы тестирования чужих приложений или новых правил поиска
исполняемых hooks/tools. C026.1/C051 исключены, C093 не возвращается под названием
Sprint; C031 относится к F4. Runtime-размещение worktree не менялось.

## Восстановление после последнего сбоя

Последняя найденная Gmail-копия C029.4: `1a0a75627acb8fca`, исходный HEAD
`8c0d7b49dff3d0783aa3e6fce4f5ffea28ae402e`. Полный архив в ней есть, но коннектор
не поддерживает чтение его MIME-типа; текстового транспорта полного архива в этом
письме не оказалось. Прочитаны полные поддерживаемые `CHECKPOINT.json` и
`changes.patch.txt`.

Восстановлен доступный F1 bundle с точным HEAD
`a51647d8f7cac029b54d7024d82e0adf8de30569`, к нему применён сохранённый cumulative
patch. SHA-256 patch совпал с исходным manifest; **все 30 изменённых Git blob**
совпали с full-index заголовками patch. Неизменённые файлы остались точной F1.
Восстановленное дерево: `519a768feb6121f9890dab0346ec24b429d4328f`.

Создан новый честно обозначенный recovery commit
`c9dac0d4c6113fd0b2a8f1ea7ee21349063de7d3`. Он не выдаётся за исходный `8c0d7b4`:
исходные девять Git commit objects и байты старых логов из последнего архивного
checkpoint недоступны; их идентификаторы и хеши сохранены как provenance.
Последующая финализация меняет документацию состояния, а не восстановленное поведение.

Для следующего восстановления используется новый накопительный checkpoint с полной
историей реально существующей recovery-ветки, sealed DB, исходным manifest/patch,
новыми логами и полным текстовым транспортом. Он восстанавливается как самостоятельный
пакет и не требует повторного исполнения задач. Правило:
[контрольная точка и восстановление](../../workflows/checkpoint-recovery.md#контрольная-точка-и-восстановление).

## Проверки и пределы выводов

При возобновлении заново проверены C017/C029.4, соседние routing/runner/catalog
контракты и статические DDD-ограничения. Граф и **полные контракты всех девяти задач**
сверены с sealed DB revision 5: девять локальных рёбер, без циклов и изолированных
членов. Снимок SQLite не изменён.

Дополнительные **200 перестановок** входных путей и деклараций подтвердили, что
сохранённый алгоритм C017 уже детерминирован; переписывать его не пришлось. Проверена
полная impact-выдача, включая причины и один шаг integration. Это не обещание
одинакового snapshot digest при разном порядке исходного JSON-запроса: router
сохраняет представление полученных фактов.

Свежие terminal/JUnit logs, bounded smoke, аудит документации и references сохраняются
в итоговом checkpoint. Уникальные тесты считаются по идентификаторам; повторные smoke
и исторические цифры из отчётов задач не прибавляются к текущей выборке.

Статический архитектурный PASS относится только к явно описанным Python-правилам,
не доказывает полный data flow, динамическую загрузку или независимость oracle.
Живая IDE и пользовательский Codex trust/install/delivery не проверены.
Gate используется только при явном подключении development routing; пользовательская
персональная конфигурация не переписывалась. F4 и product placement не начинались.
