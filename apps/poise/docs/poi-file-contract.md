# Договор ограниченного чтения reader/2

## Статус и основание

Актуально: 2026-10-28.

Самостоятельный Poise исполняет `reader.context`, `reader.read`, `reader.next`
и `reader.reset` через `bin/poise`. Договор проверяется на действительных
производителе и потребителе в отдельной копии приложения с собственной Session
и SQLite, без установленного Stride.

Основа — ответственность выбранного [SourceReader](poi-reader-comparison.md):
ограниченное чтение, явный ACK, поколения контекста и сохранение метаданных
успешного пакета. В самостоятельном reader реализованы также байтовые порции
и продолжение. ERP cache показанного текста сохраняет свою отдельную семантику.

Прежний [SourceReader](../../../docs/workflows/source-reader.md) имеет отдельные
`context/read/reset` и `source-read-result-1`. Здесь используется `reader/2`:
`count` задаёт максимальную порцию с сокращением на EOF. Это самостоятельный
версионированный интерфейс; его действующая конфигурация приведена ниже.

## Владелец и поддержанное использование

Reader принадлежит самостоятельному Poise. Он использует существующую
[Session](shell-poi.md), её фактического caller и
[собственное состояние](state-poi.md). Подготовка состояния и установление Session
предшествуют чтению. Номер Task, этап, желаемая Session и назначение роли в запрос
reader не входят. Метаданные Task остаются у владельца Task.

Поддерживаются обычные файлы с UTF-8 текстом без NUL. Пути разрешаются из явно
переданного рабочего каталога; результат содержит абсолютный канонический путь.
Содержимое возвращается как текст с исходными окончаниями строк, без удаления BOM.
Размер источника и порции ограничиваются явной конфигурацией.

При обычной записи файла его время изменения обновляется вместе с содержимым.
На время одного чтения источник сохраняют стабильным. Reader сравнивает обычные
наблюдения метаданных до и после чтения и сообщает замеченное изменение. Это
не обещание снимка всей файловой системы. Пара «размер, время изменения» различает
версии в этих условиях; одинаковые размер и сохранённое прежнее время не дают
различить изменённые байты. Хэш, подпись или проверка подмены для этого договора
не требуются.

## Выбранная файловая политика

Присутствие `paths` в рабочей конфигурации включает общую политику для
`reader.read/next`. Заполните её по [файловому договору](poi-fs-contract.md#конфигурация-poise-fs-policyv1)
и [полному примеру](../config/filesystem.example.json). Отсутствие ключа сохраняет
прежний reader; явные `roots: []` включают нейтральную политику. Присутствующее
значение проверяется согласно своей схеме. `reader.context/reset` остаются
операциями собственного состояния и `paths` не разбирают.

Общий допуск всего пакета выполняется перед первым чтением содержимого, затем
reader использует те же подготовленные назначения. Для `read` база — явный `cwd`,
для `next` — родитель первого абсолютного пути курсора. Проверки собственной
Session, поколения и ACK сохраняются. Допущенные чтение и продолжение возвращают
прежний reader/2. Отказ policy сохраняет квитанции/ACK всего пакета и возвращает
полный общий результат по [точному договору ошибок](poi-fs-contract.md#внешние-ошибки-и-продолжение).

## Конфигурация и команда

Необязательный раздел собственной конфигурации `reader` содержит известные
обязательные `schema` и `limits`. В `limits` обязательны все шесть значений ниже;
каждое — положительное целое, boolean целым не считается.

```json
{
  "reader": {
    "schema": "poise-reader/2",
    "future_note": {"owner": "example"},
    "limits": {
      "max_items": 4,
      "max_lines": 8,
      "max_range_bytes": 16,
      "max_file_bytes": 64,
      "max_output_bytes": 16,
      "max_receipts": 8,
      "future_units": ["example"]
    }
  }
}
```

`future_note` и `future_units` — корректные примеры неизвестных опций. Reader
игнорирует их смысл и сохраняет исходные значения. Неизвестные опции на обоих
уровнях остаются в исходном JSON. Известные поля и их значения проверяются.
Операции reader сохраняют файл конфигурации без перезаписи.
Пакеты API, курсоры и квитанции при этом сохраняют точную схему.

| Параметр | Значение |
| --- | --- |
| `max_items` | Максимальное число элементов одного пакета чтения |
| `max_lines` | Максимальный запрошенный `count` в строках |
| `max_range_bytes` | Максимальный запрошенный `count` в байтах |
| `max_file_bytes` | Максимальный размер исходного файла в байтах |
| `max_output_bytes` | Максимальная сумма UTF-8 байтов возвращённого текста |
| `max_receipts` | Максимальное число удерживаемых квитанций и размер списка ACK |

Указанные числа — значения примера, не скрытые значения по умолчанию. Reader
использует уже настроенные `session_store` и ожидание SQLite собственного
приложения. Дополнительный файл состояния или общая длительная блокировка не нужны.
При отсутствии раздела только операция reader сообщает `reader_not_configured`.

Полный [пример reader-конфигурации](../config/reader.example.json) задаёт также
обязательные параметры Session. Настройте шесть пределов явно. Источник загружается
в память в пределах `max_file_bytes`; выбирайте этот предел с учётом доступной
памяти. `max_output_bytes` считает только фактически возвращённый UTF-8 текст,
а не JSON-оболочку. Размеры порций ограничивают запрос, даже если файл короче.

Из корня checkout с выбранным CPython 3.13:

```sh
"${POISE_PYTHON:?Укажите абсолютный путь CPython 3.13}" -I -S -B apps/poise/bin/poise \
  --config /absolute/path/poise.json < /absolute/path/request.json
```

Пути `session_store` и generated `caller.binding_file` относятся к каталогу
конфигурации. Рабочий каталог чтения передаётся отдельно в `input.cwd`.
Известные настройки reader проверяются при выбранной операции reader;
Session и hooks используют свои действующие настройки.

## Оболочка и типы

Запрос содержит ровно `schema`, `operation`, `input`. Внешняя схема —
`stride-poise/v1`; `operation` принимает одно из четырёх имён reader ниже.
Вложенный результат каждой успешной операции имеет `schema: "poise-reader/2"`.

Успех сохраняет внешнюю форму приложения:

```json
{"schema":"stride-poise/v1","status":"ok","result":{"schema":"poise-reader/2","generation":1,"reason":"startup","event_id":null},"error":null,"evidence":[]}
```

Это успешный ответ `reader.context` для начального контекста. Точные поля остальных
результатов заданы ниже. Успешный процесс завершается с exit 0. Reader не создаёт файлов вывода
команд, поэтому `evidence` пуст.

Обычный отказ reader содержит ровно внешние `schema`, `status`, `result: null`,
`error: {code, details, action}`, `evidence: []`. При отказе выбранной файловой
политики `result` содержит полный общий результат по
[файловому договору](poi-fs-contract.md#внешние-ошибки-и-продолжение). `rejected` имеет exit 2,
`unavailable` — exit 1. Ошибка устаревшего продолжения относится к текущей операции,
а не запрещает запуск приложения.

Все поля API обязательны, если явно не описано отсутствие. Целые значения
исключают boolean. Непустая строка содержит значимый текст без NUL. Списки ACK
содержат уникальные непустые идентификаторы; их длина ограничена `max_receipts`.

## Контекст и первое обращение

`reader.context` принимает ровно `{}`. Результат содержит ровно:

| Поле | Тип и смысл |
| --- | --- |
| `schema` | `poise-reader/2` |
| `generation` | Целое не меньше 1 |
| `reason` | `startup`, `resume`, `compact`, `clear`, `fork` или `manual` |
| `event_id` | Непустая строка либо `null` для начального контекста |

При существующей Session без reader-состояния `context` сохраняет начальные
`generation: 1`, `reason: startup`, `event_id: null` и пустые квитанции.
Повтор наблюдает то же состояние.

`reader.reset` принимает ровно `{reason, event_id}` с указанными типами.
Новый относительно последнего `event_id` повышает поколение и очищает возможность
подавлять чтения прежними квитанциями. Результат имеет форму контекста.
Тот же **последний** ID с той же причиной возвращает прежний результат; это
не обещание повторного применения всей истории событий.
Тот же последний `event_id` с другой причиной получает `reader_event_conflict`,
`rejected`, exit 2, `details: {event_id}` и `action: reader:reset`.
Поколение, последняя причина, ID события и остальные reader-метаданные сохраняются.

Первый `reset` без reader-состояния действует в одной операции: концептуально
начинает с поколения 1, применяет событие и сохраняет поколение 2 с переданными
причиной, ID и пустыми квитанциями. Предварительный `context` не требуется.
Повтор первого события сохраняет поколение 2. Явный пользовательский сброс
использует `manual`; происхождение настоящего события хоста подтверждает его
действующая интеграция.

Корректные `read/next` без reader-контекста возвращают `reader_context_missing`,
`unavailable`, exit 1, `details: {}`, `action: reader:context`. Они не создают
reader-состояние. После `context` чтение использует возвращённое поколение 1;
после первого `reset` — поколение 2. При существующем ином поколении отказ
`reader_context_changed` сообщает текущее значение и сохраняет состояние.

## Запрос диапазона и продолжения

`reader.read.input` содержит ровно:

| Поле | Тип и смысл |
| --- | --- |
| `cwd` | Непустой абсолютный путь к рабочему каталогу |
| `generation` | Текущее положительное целое поколение |
| `acknowledged` | Список IDs реально полученных квитанций |
| `reads` | От 1 до `max_items` элементов |

Каждый элемент `reads` содержит ровно `path`, `range`, `reread`, `reason`.
`path` — непустой абсолютный или относительный путь. `range` содержит ровно
`unit`, `start`, `count`: единица `lines` или `bytes`, целая позиция начала и
положительное целое максимальное количество. Для строк начало не меньше 1,
для байтов — не меньше 0. `reread` — boolean; `reason` — строка, непустая при
`reread: true`.

`reader.next.input` содержит ровно `generation`, `acknowledged`, `reads`.
Элемент `reads` содержит ровно `cursor`, `count`, `reread`, `reason`.
Количество и правила повторного чтения те же; путь, единица, начало, версия и
поколение берутся из курсора. `cwd` не нужен: путь курсора абсолютный.

Курсор содержит ровно:

| Поле | Тип и смысл |
| --- | --- |
| `path` | Абсолютный канонический путь |
| `unit` | `lines` или `bytes` |
| `next` | Следующее начало в соответствующей единице |
| `version` | Объект версии файла |
| `generation` | Положительное поколение контекста |

Курсор — прозрачные данные позиции, не подписанный токен и не полномочие доступа.
Его используют в той же Session и контексте. Повтор одного курсора разрешён;
reader не требует равенства с неявной «последней позицией». Сам ACK позицию
не двигает. Новое поколение требует свежего явного диапазона.

## Строки, байты и EOF

`count` ограничивает максимальную порцию. Последняя порция сокращается до
доступного содержимого. Позиция ровно после конца — допустимое пустое завершение;
позиция дальше неё получает `reader_bounds`.

| Единица | Начало | Фактический `count` | Начало ровно на EOF |
| --- | --- | --- | --- |
| `lines` | Нумерация строк с 1 | Число возвращённых строк | Число строк + 1 |
| `bytes` | Смещение исходных UTF-8 байтов с 0 | Число возвращённых байтов | Размер файла |

Пустой файл имеет EOF в строковой позиции 1 и байтовой позиции 0.
Сохраняется сегментация выбранного SourceReader: LF, CR, CRLF, VT, FF, FS, GS,
RS, NEL, LS, PS, с разделителем в возвращаемой строке. Завершающий разделитель
не создаёт дополнительную пустую строку. Это семантика текущего
`splitlines(keepends=True)`, а не требование конкретного способа реализации.

Байтовое начало располагается на границе UTF-8 символа. Возвращается наибольший
целый префикс символов в пределах `count`. Если следующий символ целиком не
помещается, `reader_count_too_small` сообщает `minimum_count`; reader не создаёт
курсора без продвижения. Отсутствие границы символа — `reader_invalid_input`
с указателем соответствующего `start`.

Для `A\nЖ🙂\nZ` исходный размер равен 10 байтам. Запрос байтов с начала 2 и
`count: 5` возвращает `Ж` (2 байта), продолжение начинается с 4. Следующая
порция с `count: 4` возвращает `🙂` (4 байта), продолжение начинается с 8.

## Результат чтения

Результат `read/next` содержит ровно `schema`, `generation`, `items`, `text_bytes`.
Элементы соответствуют входному порядку. Каждый содержит:

| Поле | Значение |
| --- | --- |
| `path` | Канонический путь |
| `version` | Версия прочитанного файла |
| `range` | Ровно `unit`, `start`, фактический `count` |
| `status` | `read`, `reread`, `unchanged` или `eof` |
| `receipt_id` | Непустой непрозрачный ID; для пустого EOF — `null` |
| `eof` | Boolean: достигнут конец файла |
| `next` | Следующий курсор либо `null` на EOF |
| `text` | Строка для `read/reread/eof`; отсутствует только при `unchanged` |

У непустой последней порции обычный статус `read/reread/unchanged`, `eof: true`
и `next: null`. Пустое завершение имеет `status: eof`, `text: ""`, `count: 0`,
`receipt_id: null`, `eof: true`, `next: null`; квитанция не создаётся.

Для строк следующее начало равно `start + фактический count`; для байтов —
`start + число возвращённых байтов`. `text_bytes` — сумма UTF-8 байтов фактически
включённых `text`, без метаданных JSON и подавленного текста. При `unchanged`
координаты и завершение остаются определёнными, хотя текст отсутствует.

## Версия, ACK и эффекты

Версия содержит ровно `size_bytes` (целое не меньше 0) и `modified_ns` (целое),
наблюдаемые у источника. `next` сравнивает сохранённую версию с текущей до выбора
порции. При различии сообщает `reader_version_changed`; клиент делает свежий
явный `read`. Новый `read` выбирает текущую версию обычным образом.

Непустой результат получает квитанцию своей Session, поколения, пути, версии,
единицы и фактического диапазона. Повтор удерживаемой идентичности использует
её квитанцию. Пока клиент не передал её ID в ACK, повтор возвращает текст.
Подтверждённое совпадение даёт `unchanged`; `reread: true` с причиной вновь
возвращает текст. IDs не обязаны быть хэшами.

Квитанции удерживаются в пределах `max_receipts`. Последующие порции могут
вытеснить более ранние, в том числе внутри одного успешного пакета: при ёмкости
одна квитанция пакет из двух разных непустых порций возвращает обе, а удерживается
последняя. Число элементов пакета и ёмкость квитанций настраиваются отдельно.

Если ACK содержит уже вытесненный или неизвестный ID, операция сообщает
`reader_receipt_unknown`. Для получения нужного текста выполните явный
`reader.read` в текущем поколении с нужным диапазоном и `acknowledged: []`.
Примите текст и используйте квитанцию из этого нового ответа для последующего
ACK. Поколение сохраняется.
При намеренном повторном чтении по удерживаемой квитанции используйте
`reread: true` с содержательной причиной.

Вытеснение позволяет повторное получение текста и сохраняет смысл подтверждения.
После восстановления контекста выполните предусмотренный reset и используйте
его новое поколение. Получение текста подтверждайте явным ACK с выданным ID.

Reader проверяет пакет, читает все источники и считает вывод до записи его
квитанций и ACK. Обычный отказ reader возвращает `result: null` и сохраняет прежние
метаданные всего пакета. При выбранной policy её отказ также сохраняет метаданные,
но возвращает полный `poise-fs-result/v1` в `result` по файловому договору.
Внешняя файловая система этим не откатывается.
Композиция `reset` с последующей внешней операцией также не получает обещания
общего отката: отдельно успешный сброс уже мог сохраниться.

Запрошенные `count` ограничены своей единицей; размер файла — `max_file_bytes`.
Сумма возвращённого текста ограничена `max_output_bytes`. Строка возвращается
целиком; для меньшей текстовой порции используют байтовый режим с достаточным
числом байтов для целого символа.

## Отказы операции

Обязательные детали каждого отказа заданы таблицей. Указатель `field` — JSON
Pointer в запросе: внутри одного имени `~` записывается как `~0`, `/` — как `~1`.
Проверка входа предшествует изменению reader-метаданных.
Неподдержанная внешняя схема и отсутствие Session остаются у существующего
владельца внешнего входа и Session.

Недоступный источник, неподдержанный тип файла, текст вне UTF-8, NUL и превышение
`max_file_bytes` относятся к `reader_source_unavailable`. Неверное значение
известного поля запроса, неизвестное поле API, превышение запрошенным `count`
лимита своей единицы и байтовое начало внутри символа относятся к
`reader_invalid_input` с указателем этого поля. Если оба поколения переданного
запроса и курсора заданы корректно, но отличаются от текущего, результат —
`reader_context_changed` с текущим поколением. Значения известной конфигурации
проверяет её существующий владелец, как и остальные параметры приложения.

| `code` | Статус / exit | Точные `details` | `action` |
| --- | --- | --- | --- |
| `reader_not_configured` | unavailable / 1 | `{}` | `configure:reader` |

## Последовательность правильного использования

Для reader подготовьте собственное состояние и Session по действующему
руководству, задайте известные лимиты и выберите нужный документ.

1. Получите `reader.context` или выполните явный `reader.reset` и используйте
   возвращённое поколение.
2. Передайте конечный диапазон в `reader.read`. Получите текст, квитанцию,
   фактический диапазон и `next`.
3. После получения текста передайте его квитанцию в последующем `acknowledged`.
   Для следующей порции передайте возвращённый курсор в `reader.next`.
4. На `eof: true` завершите последовательное чтение. После обычного изменения
   файла выберите свежий явный диапазон текущей версии.
5. После восстановления контекста выполните сброс и перечитайте необходимые
   материалы с новым поколением. Для намеренного повторного получения текста
   используйте `reread: true` и содержательную причину.

Пример правильного запроса после получения поколения 1:

```json
{
  "schema": "stride-poise/v1",
  "operation": "reader.read",
  "input": {
    "cwd": "/work/source",
    "generation": 1,
    "acknowledged": [],
    "reads": [
      {
        "path": "sample.txt",
        "range": {"unit": "lines", "start": 1, "count": 1},
        "reread": false,
        "reason": ""
      }
    ]
  }
}
```

## Полный пример отдельной установки

В Bash из корня checkout задайте `POISE_PYTHON` абсолютным путём CPython 3.13.
Последовательность копирует только приложение Poise, создаёт собственные конфиги,
состояние и generated caller. Оба конфига находятся рядом; `database` состояния
выбирает тот же относительный путь, что `session_store` reader.

```bash
# reader-quickstart
set -e
POISE_READER_ROOT="$(mktemp -d)"
cp -R apps/poise "$POISE_READER_ROOT/poise"
POISE_APP="$POISE_READER_ROOT/poise"
mkdir -p "$POISE_READER_ROOT/config"
cp "$POISE_APP/config/reader.example.json" "$POISE_READER_ROOT/config/poise.json"
cp "$POISE_APP/config/state.example.json" "$POISE_READER_ROOT/config/state.json"
"$POISE_PYTHON" - "$POISE_READER_ROOT" <<'PYSETUP'
import json
from pathlib import Path
import sys

root = Path(sys.argv[1])
reader = json.loads((root / 'config/poise.json').read_text())
state_path = root / 'config/state.json'
state = json.loads(state_path.read_text())
state['database'] = reader['session_store']
state_path.write_text(json.dumps(state, ensure_ascii=False, indent=2) + '\n')
(root / 'sample.txt').write_text('A\nЖ🙂\nZ', encoding='utf-8')
PYSETUP
printf '%s\n' '{"schema":"poise-state/v1","operation":"prepare","input":{}}' |
  "$POISE_PYTHON" -I -S -B "$POISE_APP/bin/poise-state" \
    --config "$POISE_READER_ROOT/config/state.json"
"$POISE_PYTHON" - "$POISE_APP" "$POISE_READER_ROOT" <<'PYCLIENT'
import json
import os
from pathlib import Path
import subprocess
import sys

app, root = map(Path, sys.argv[1:])
environment = os.environ.copy()
for name in ('CODEX_SESSION_ID', 'CODEX_THREAD_ID'):
    environment.pop(name, None)
calls = []

def call(operation, value):
    packet = {'schema': 'stride-poise/v1', 'operation': operation, 'input': value}
    payload = json.dumps(packet, ensure_ascii=False) + '\n'
    child = subprocess.run([sys.executable, '-I', '-S', '-B', str(app / 'bin/poise'),
        '--config', str(root / 'config/poise.json')],
        input=payload.encode('utf-8'), capture_output=True, env=environment, check=False)
    calls.append({'request': json.loads(payload), 'stdin': payload, 'exit': child.returncode,
        'stdout': child.stdout.decode('utf-8'), 'stderr': child.stderr.decode('utf-8')})
    (root / 'example-calls.json').write_text(json.dumps(calls, ensure_ascii=False, indent=2) + '\n')
    child.check_returncode()
    print(child.stdout.decode('utf-8'), end='')
    return json.loads(child.stdout)['result']

call('session.ensure', {})
context = call('reader.context', {})
generation = context['generation']
line = {'path': 'sample.txt', 'range': {'unit': 'lines', 'start': 1, 'count': 1},
        'reread': False, 'reason': ''}
first = call('reader.read', {'cwd': str(root), 'generation': generation,
    'acknowledged': [], 'reads': [line]})
first_id = first['items'][0]['receipt_id']
byte = {'path': 'sample.txt', 'range': {'unit': 'bytes', 'start': 2, 'count': 5},
        'reread': False, 'reason': ''}
portion = call('reader.read', {'cwd': str(root), 'generation': generation,
    'acknowledged': [first_id], 'reads': [byte]})
while True:
    item = portion['items'][0]
    last_id = item['receipt_id']
    if item['eof']:
        break
    portion = call('reader.next', {'generation': generation, 'acknowledged': [last_id],
        'reads': [{'cursor': item['next'], 'count': 4, 'reread': False, 'reason': ''}]})
call('reader.read', {'cwd': str(root), 'generation': generation,
    'acknowledged': [first_id, last_id], 'reads': [line]})
line['reread'], line['reason'] = True, 'Повторное чтение выбранной строки'
call('reader.read', {'cwd': str(root), 'generation': generation,
    'acknowledged': [], 'reads': [line]})
reset = {'reason': 'manual', 'event_id': 'reader-example-context-1'}
call('reader.reset', reset)
context = call('reader.reset', reset)
line['reread'], line['reason'] = False, ''
call('reader.read', {'cwd': str(root), 'generation': context['generation'],
    'acknowledged': [], 'reads': [line]})
PYCLIENT
printf 'Reader example: %s\n' "$POISE_READER_ROOT"
```

Очистка native-переменных относится только к отдельным дочерним процессам
generated-примера. Native identity текущей оболочки и её launcher сохраняются.
Собственный binding повторно выбирает ту же Session во всех вызовах.

Все вызовы завершаются exit `0`, `status="ok"`, с пустым stderr. Подготовка даёт
версию `1`; `session.ensure` создаёт Session с `role: null`. Начальный reader-контекст
имеет поколение `1`. Строка возвращает `A\n`, фактический `count: 1` и `text_bytes: 2`.
Байтовая порция возвращает `Ж` (2 байта), последующие — `🙂` (4 байта) и `\nZ`
(2 байта, `eof: true`, `next: null`). Подтверждённая первая строка возвращает
`status: "unchanged"`, `text_bytes: 0`; намеренный повтор — `status: "reread"`
и исходный текст. Два вызова одного reset возвращают поколение `2`; свежий диапазон
в нём снова возвращает строку с `status: "read"`.

Полные запросы и ответы сохранены в `example-calls.json` указанного каталога.
Для последующей работы используйте ту же конфигурацию, базу и caller binding;
выбирайте диапазоны действительных источников, получайте текущее поколение и
передавайте полученные квитанции после приёма текста. После обычного изменения
источника выберите свежий диапазон; после восстановления контекста выполните явный
reset и используйте возвращённое поколение.

## Независимые примеры и проверка реализации

[Буквальные примеры](../tests/fixtures/reader-contract/vectors.json) задают независимые
исходные тексты, версии, запросы, ответы и эффекты. Их исходная метка проектных
примеров относится к этим данным, а не к доступности поставленного reader. Примеры
сами по себе не являются журналом исполнения. Действительный производитель и
потребитель проверяются текущими тестами.

`$ROOT` обозначает выбранную тестовую директорию. Объявленные `${r1}` связываются
один раз только в полях ID квитанций и ACK. Пути нормализуются отдельно; тексты,
причины, числа, версии, EOF и ошибки сравниваются буквально. Успешный `next` получает
действительный ранее проверенный курсор. Эффекты проверяются через публичные
повторы и снимки собственного состояния, без требования приватной JSON-структуры.

Из корня checkout с выбранным Python задайте `POISE_READER_CHECK_OUTPUT`
абсолютным путём собственного каталога отчётов:

```bash
"$POISE_PYTHON" -B apps/poise/tests/test_reader.py --suite delivery \
  --output-root "$POISE_READER_CHECK_OUTPUT/delivery"
"$POISE_PYTHON" -B apps/poise/tests/test_reader.py --suite behavior \
  --output-root "$POISE_READER_CHECK_OUTPUT/behavior"
```

Оба вызова имеют exit `0` на текущей реализации. `delivery` проверяет доступность
операции после реальной подготовки Session и различает её от ошибок тестового окружения. `behavior`
исполняет четыре группы: договор порций, собственные Session и квитанции,
конфигурация и источники, атомарность отказа пакета. В каждом каталоге
`reader-details.json` сохраняет полные наблюдения.

Проверка ссылок и чтение описания подтверждают согласованность документации.
Отдельные реальные запуски подтверждают работу команд и результатов.
