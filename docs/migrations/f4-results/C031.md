## Результат

[Явная операция diagnose](../../operations/hook-effect-diagnostics.md#диагностика-фактических-эффектов-hooks)
координирует существующих владельцев. Установка группы hooks, запись native события,
эффект и trust хоста — разные свидетельства. Поддержаны одиночные и пакетные запросы.
Все формы и конкретные `probe_cwd` проверяются до активных probes. Без такого аргумента
диагностика не запускает процессы, runtime bootstrap, restore_context или telemetry replay.

Сопоставляются поколение SourceReader, исходный receipt InteractionStore и immutable
receipt отмены RegisteredCheckRunner. Последний сохраняет session/start/end event IDs;
для подтверждения требуются также терминальный выход сигналом и отсутствие timeout.
Старое `cancelled=true` без корреляции не является подтверждением. Stop наблюдается,
но доставка его ответа не имеет устойчивого receipt и не объявляется подтверждённой.
Неподдержанный native event и отсутствие записи дают явные неполные результаты.

Runtime provenance относится к текущему диагностическому процессу. Он не выбирает иной
исполняемый экземпляр, не меняет пути hooks/config/tools и не становится политикой
для других репозиториев. Сводка spool относится к очереди целиком, не к выбранному
hook. Ошибки опциональной телеметрии не отменяют подтверждённый эффект.

Добавлено чтение существующих owner stores без инициализации/миграций; SQL выбирает
конкретные записи и ограничивает размер JSON. Специальные файлы и превышение bounds
не дают успешного свидетельства. Чтения разных владельцев — независимые снимки.

## Исправление соседнего архитектурного дефекта

В C028.5 прямой импорт `datetime` в `accounting/domain.py` нарушал действующий запрет.
Это воспроизведено перед исправлением. Валидация переданной даты перенесена в уже
существующий `accounting/clock.py`: исходная строка, смещение, параметры, null/0 и
отсутствующие длительности не преобразуются. Тесты исходных метрик сохранены.

## Проверка

Новый набор содержит 44 теста C031: подтверждённые и отсутствующие эффекты, старые,
чужие и повреждённые receipts, read-only/WAL, ограничения пакета, отдельный реальный
CLI subprocess, явный probe с относительным cwd и настоящий отменяемый процесс.
RED получен через действующий CLI (`diagnose` ещё неизвестна), не через import error.
Во время проверки исправлен конкретный дефект нормализации относительного probe_cwd.

Шесть непересекающихся завершённых групп дали 191 PASS (59 + 36 + 41 + 22 + 3 + 30).
44 новых теста уже входят в 59. Bounded smoke: 6 PASS, отдельно, с пересечением с
регрессионной выборкой. Full suite не запускался. Существующие 10 fork warnings в
hook-тестах сохранены; два прерванных широких выбранных запуска не учтены как PASS.
Первый subprocess-тест setup выявил отсутствие PYTHONPATH в тестовом окружении:
исправлена только среда конкретного запуска, а не политика продукта или сам fixture.

Независимое ревью, живой пользовательский хост/IDE и интеграция не выполнялись.
Task DB не изменялась. Точные commit, SHA-256, логи и Gmail readback фиксируются
в накопительном checkpoint и внешнем delivery receipt.
