## Реальные находки до выдачи среза
1. **A → B → A:** дедупликация по всей истории оставляла latest=B. Добавлен red test, исправлена дедупликация только относительно текущей версии. Повтор текущего A no-op; возврат A после B создаёт новый текущий слой. `11-review-red.txt` → `12-evidence-review-green.txt`.
2. **Ошибка инструмента как отрицание продукта:** subject с неожиданным выводом мог получить verified/not_satisfied. Добавлен red CLI/API test, явные правила распознавания observation и отдельный interpretable. Произвольный traceback не доказательство отрицания. `13-recognition-red.txt` → `14-recognition-green.txt`.
3. **Изменение target во время наблюдения:** возвращалось awaiting_continuation до проверки нового дерева. Проверка moved перед возвратом агенту: аргумент по неопределённому состоянию не запрашивается. `20-target-review-red.txt` → `22-review-green.txt`.
4. **Resume push после изменения env:** ветка публикации могла обойти новый execution signature. К publication добавлен execution_key и проверка пригодности receipts. Реальный недоступный bare remote и изменение LANG воспроизвели ошибку. `21-publication-review-red.txt` → `22-review-green.txt`.

## Проверенные границы
Domain не импортирует I/O. Handlers не выполняют tests/SQL. Semantic proof changes сохраняет TaskRepository вместе с Task version/event. Command receipts — через EvidenceCommands и repository, без runtime SQL. Неполный argument не может быть обойдён прямым mark_verified. Review не принимает собственный argument и должен ссылаться на текущую revision. Cancellation не требует evidence.

## Инфраструктура проверки
Один механический edit fixtures добавил неуместную ссылку proc в уже созданном сценарии; удалён лишний повтор присваивания, старая проверка сохранена. Несколько общих запусков остановлены лимитом контейнерного tool, не объявлены PASS.
