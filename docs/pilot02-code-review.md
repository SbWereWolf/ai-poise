## Осмотр тестов

Проверки helper не заменяют реальные subprocess собственными mocks. Fixture создаёт
реальный pytest-отказ с диагностическим файлом; другая fixture намеренно оставляет code=0
при failure в XML. Тест timeout ждёт реальное завершение группы, сохраняя частичный workspace.
Отсутствующий/невалидный/пустой XML проверяются отдельными точными входами.

Первый RED — отсутствие новых функций parse_junit/run_package и примера продолжения.
Это контрактный RED, не доказательство старого дефекта. Отдельный before/after эксперимент
реально исполняет старый и новый runner на одинаковых fixture-тестах: старый удаляет
диагностику; при принудительном code=0 старый возвращает success при нуле пройденных тестов.

При осмотре контрактов исправлены имена полей test fixture: существующие receipts используют
`method`, а не `method_id`. Действующий Evidence API ради теста не менялся.

## Владельцы и границы

* Runtime/domain/storage код не менялся. Общая механика команд используется повторно.
* Пример исполнения не присваивает статусы и не пишет SQL/config. Все изменения Task и
  handoff/transfer идут через WorkTools; TaskQueries применяется только для чтения.
* Точные команды не угадываются примером: execution использует сохранённый реестр.
* Исходники target неизменны; пример не принимает execution и не начинает analysis.
* Нет миграции, совместимого parser или новых defaults. Retention успешных workspace —
  новый обязательный параметр вспомогательного runner.

## Исправления по осмотру

Хэши проверяющего инструмента добавлены к fingerprint: иначе можно было изменить runner,
сохранив неизменность только src/tests. Это проверено отдельным тестом.
Успех требует одновременно terminal exit и содержательный JUnit. XML failure не становится
успехом от кода 0. Re-run не может затереть уже существующий package workspace.

## Остаточные границы

Первопричина всех семи исторических отказов PILOT-01 не доказана задним числом. Новая
диагностика исправляет потерю данных, а не автоматически причину каждого старого отказа.
Внешний package timeout не изменяет лимиты внутри тестов; никаких автоматических retry нет.
Исторический store не поставлялся; реальный пилот честно воспроизводит прежний план новым
Task API. Теперь сохранён переносимый checkpoint, чтобы устранить эту потерю контекста.
