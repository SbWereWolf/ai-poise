## Сквозные маршруты
1. Прежний CLI demo: регрессионный RED → осмотр тестов → реализация GREEN → осмотр кода → принятие.
2. Новый content demo: минимумы типа + дополнительные требования задачи; две независимые trace chains; сначала planned-ссылка на будущую документацию, затем реальный документ; доработка после precheck; method ID и поздний аргумент/verdict; повторный осмотр с сохранением прошлых layers; завершение.
3. Новый метод добавлен в том же result packet, в котором впервые появляется ссылка trace; он действительно запущен exact argv, а его расписание сохранено для позднего этапа.
4. Реальный SQL trigger откатывает submission, section/trace/contract/method изменения вместе. Старый store v2 отклонён без изменения байтов. Прямой вызов mark_verified не обходит gates.

Учебные коммиты публикуются в локальный bare remote. Содержательные statements осмотра в demos — тестовые fixtures, не доказательство качественного review моделью. Никакие тесты внешнего пользовательского продукта не запускались.
