## Границы

`TransferPolicy`/`TransferRequest` проверяют явный контракт без I/O. `TransferCommands` вызывает порт; WorkTools принимает тот же пакетный envelope. SQLite transfer adapter выбирает согласованный scoped snapshot и координирует Task/Sprint repositories. Файловый/Git adapter формирует и принимает пакет; он не принимает пользовательский результат и не меняет этапы.

Новые корневой и src/AGENTS.md написаны на английском. В корне закреплены цель и порядок работы, в src — DDD, конфигурация, пакетность и повторное использование. В реестре кандидатов отмечены только явно выбранные пользователем правила.

## Обнаруженные и исправленные дефекты

**Порядок строк снимка.** Первое прохождение полного спринта обнаружило несовпадение fingerprint из-за различного порядка SQL-выборки одинаковых записей. Проверка целостности теперь сравнивает каноническое множество строк; seq/version продолжают задавать содержательный порядок. Отдельный тест проверяет, что перестановка не меняет fingerprint, а изменение строки меняет.

**Digest артефакта.** Первоначально новая копия файла могла быть целостной, но не совпадать с прежним зарегистрированным evidence. Добавлен RED-регрессионный тест и проверка source registry до упаковки. Изменённый файл не переносится как прежнее доказательство.

**Порядок методов.** SQLite index scan изменял порядок зарегистрированных RED/GREEN методов при переносе. Регрессия воспроизведена до исправления. Явно сохраняется порядок регистрации методов; import не перестраивает расписание по алфавиту ID.

**Демонстрационный контракт.** Первый CLI-demo не создал обязательный финальный result.md учебной задачи; сама проверка правильно отказала. Пример исправлен: артефакт создаётся через пакетный инструмент, требование задачи не ослаблено.

## Что намеренно не разрабатывалось

Нет синхронизации отдельных участников уже существующего спринта, перезаписи/merge совпавших owner IDs, возвращения обновлений в прежний store, универсальной миграции и автоматического внешнего upload. Нет заявления о проверенном новом окружении лишь из-за наличия source receipts. Исходники и внешние конфиги не копируются по произвольному обнаруженному пути.

Архив считается входом явной пользовательской операции; digest обеспечивает целостность передачи, а не криптографическую аутентификацию автора. Точные команды из задачи не запускаются импортом; они исполняются последующей явно начатой работой через обычный verify.
