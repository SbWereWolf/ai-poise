# Repository documentation owner map

This is a lookup procedure, not a fixed target directory taxonomy. Resolve documentation owners from the selected project's versioned index, applicable agent rules and the explicitly selected checkout path. Read target settings as source facts; Poise-required routing/file maps, commands, versions and runtime/browser parameters remain inside AI poise configuration.

## Find the narrow owner

Start at the target's current documentation index or root/nearest agent instructions. Locate the owning application/tool/domain and its existing architecture, configuration, manual, runbook, requirements and verification documents. Check that cited paths exist. Do not create a guessed `docs/products`, `platform-infrastructure`, compose layout, product name or legacy ERP tree.

Map each changed fact to its owner: responsibilities/dependency direction to architecture; operator steps/prerequisites/outputs/errors to the tool manual or runbook; environment inputs to the authorized configuration surface; acceptance and test boundaries to the verification owner; user-visible lifecycle/roles to the relevant product/domain manual. Cross-application integration belongs to its actual integration owner, not a duplicated umbrella registry.

When invoking a specific tool, read that tool's current command/error/output contract. Keep detailed information with the owning tool/application rather than a second general tooling contract. Shared foundations describe durable principles; agent-facing references project those principles without becoming a competing source.

## Poise's own current entry points

When the selected target is AI poise, begin with its [documentation index](../../docs/README.md), [architecture boundaries](../../docs/architecture/boundaries.md), [project setup](../../docs/configuration/project-setup.md), [Task DB backups](../../docs/task-db-backups.md) and [workflow evidence](../../docs/workflows/evidence.md) as appropriate. These are this repository's entry points, not mandatory paths in other targets. Follow the owning API for managed Task/configuration/backup state; documentation lookup never authorizes direct SQLite or managed-configuration writes.

## Record impact without a second registry

Use existing Poise Task content, artifact and evidence owners to record changed authoritative documents, the rationale and verified paths. Do not migrate DOC-IMPACT.md or TRACEABILITY.md. Update the actual human-facing guide and agent projection in the same authorized behavior change when required; no stale owner guidance may be hidden by a passing smoke test. If the owner/path/authorization is missing, report the exact dependency instead of inventing a document or broadening the Task scope.
