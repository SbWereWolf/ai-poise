# Хранение DDD-07B

Редакция: **2026-09-07T00:25:38+05:00**.

Формат проекта: `ddd-transfer-10`. SQLite `user_version=11`. Runtime-зависимости остаются стандартной библиотекой CPython 3.13 и Git. Требуется новый пустой store; миграция прежних схем не выполняется.

Новые таблицы:

| Таблица | Владелец и назначение |
|---|---|
| `transfer_requests` | Transfer: actor/request identity, исходное намерение и состояние prepared/complete |
| `transfer_imports` | Transfer: один receipt на принятый digest пакета; повтор не переустанавливает старое состояние |
| `transfer_locations` | Transfer location adapter: подтверждённые соответствия исходных и действующих физических roots для Task; FK к tasks |

Исходный snapshot содержит обычную схему без живых bindings/sessions и данных посторонних владельцев. Репозитории Task и Sprint имеют отдельный контролируемый метод rehydration snapshot отсутствующего владельца. Это не public API произвольной записи таблиц и не альтернативный lifecycle.

Submission sequence IDs переназначаются при публикации; current_submission, FK секций, результатов, workflow layers и записанные ссылки task events переназначаются согласованно. Порядок зарегистрированных методов сохраняется. События сообщений проверяются на identity conflict и не получают вторую primary binding.

`ArtifactRegistry` использует scope + owner + относительный путь для идентичности файла. Полные исходные command receipts/разборы и содержательные тексты не переписываются. Адресуемые технические поля результата разрешаются через location adapter; это перенос расположения, не пересмотр доказательства.

Внешний lock сериализует короткие SQLite transactions. Дополнительный lock отдельной операции защищает её технический каталог от одновременного повторения. Bundle, копирование файлов и команды Git не выполняются внутри store transaction.

Предварительно созданные директории при I/O/SQL отказе не объявляются рабочими задачами. Завершение той же подготовленной операции разрешено только при неизменных target locations и совпадении сохранённого содержимого. Произвольный reset, перезапись существующей задачи и автоматический merge запрещены.
