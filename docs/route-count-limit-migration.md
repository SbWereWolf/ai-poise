# Миграция ограничений количества переходов route

AI poise больше не использует `max_transitions` и `max_stage_visits`. Актуальный объект `route` содержит только `entry`; счётчики `visits` и `transitions` остаются в состоянии задачи исключительно для истории, identity и аудита.

Миграция является явной, однонаправленной и идемпотентной. Она удаляет два устаревших поля из всех процессов, перечисленных в `project.json`, и из снимка `process` каждой сохранённой задачи. Goal, требования, материалы, evidence, Git/execution state, текущий этап, iteration и `task_workflows` не изменяются.

Перед запуском остановите агентов и процессы, которые могут писать Task DB. Сначала создайте операторскую резервную копию, затем выполните миграцию:

```bash
.venv/bin/poise backup create --config /absolute/path/to/project.json
.venv/bin/poise route-migrate --config /absolute/path/to/project.json
```

Успешный ответ содержит `status=migrated` и количество изменённых процессов и task snapshots. Повторный запуск безопасен и возвращает нулевые количества. Частичная старая форма route, неизвестные поля или структурно неверный граф отклоняются до записи. Если процесс был прерван между атомарными публикациями файлов, устраните причину и повторите ту же команду: она принимает смесь уже мигрированных и исходных полных документов. SQLite-изменения выполняются одной транзакцией под project state lock.

Для отката при остановленных writers используйте имя созданной копии:

```bash
.venv/bin/poise backup restore --config /absolute/path/to/project.json BACKUP_NAME
```

Восстановление Task DB не откатывает файлы процессов. Если нужен полный откат версии приложения, восстановите также прежние process-файлы из того же проверенного релиза.
