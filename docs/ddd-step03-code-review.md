# Осмотр кода и исправлений DDD-03

Осмотр выполнялся тем же агентом, не независимым reviewer. Проверены Task/graph boundaries, candidate/verified bookkeeping, сохранение и реальное исполнение примеров.

## Исправлено при осмотре

1. **Продолжение на изменённом после доклада коде.** Контрпример: verify дерева A → внешнее изменение B → continue начинало read-only этап с B как baseline без подтверждения. Новый регрессионный тест сначала получил DID NOT RAISE. TaskCommands теперь сравнивает наблюдаемое entry_tree с последним verified_tree перед переходом; требуется явный rework. Изменение и переход не записываются частично.
2. **Позиция graph проверялась после индексирования.** Валидация типа/диапазона stage_index перенесена до обращения к счётчику посещений; повреждённая позиция даёт доменную ошибку, не IndexError.
3. **Последний индекс использовался для task artifact gate.** Теперь условие берётся из вычисленного terminal edge, поэтому короткий путь inspect→null проверяет task artifacts, даже если revise-узлы стоят дальше в массиве. Это было исправлено при интеграции и покрыто реальным тестом.
4. **Новое поколение формата должно быть явным во всех примерах.** Старые fixtures обновлены к обязательным route/handler/stage_work; нет runtime конвертации старого формата.

5. **Лимит общего smoke-примера.** Четыре реальные CLI-истории в одном subprocess не уложились в 120 секунд: три завершились, четвёртая была прервана тестовым драйвером. Увеличен только бюджет этого сквозного теста до 240 секунд; ограничения команд/переходов продукта не менялись. Прерванный запуск не засчитан PASS.

## Что подтверждается тестами

Кандидат F1→F2 не накапливает непроверенные findings; повтор payload/verify не дублирует записи. Resolutions и решения приняты/отклонены разделены. После rejected сохраняется открытая finding, и следующий revise обязан представить новое предложение. Новая finding на повторном осмотре запускает ещё один переход по конфигу. SQL rollback захватывает workflow и content вместе.

Граф не выбирает следующий этап по позиции массива; все этапы достижимы, есть путь завершения, обратные маршруты bounded. Приём и продолжение различаются. Шаг inspect не изменяет target. Проверки содержимого продолжают выполняться на стадии исправления.

## Границы

Нет claim race/scheduler и cancel во время test run: они исключены пользовательской моделью. Нет универсального evaluator истинности evidence. Отсутствующие hooks/adapters не имитируются. Первоначальная библиотека feedback task-local и blocking; интеграция внешних продуктовых находок отдельной review task будет другим контрактом, а не автоматическим ослаблением этого.
