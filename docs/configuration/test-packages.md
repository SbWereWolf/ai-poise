# Test packages AI poise

`config/testing/test-packages.json` описывает только тестовые пакеты **самой кодовой базы AI poise**. Это не схема, которую Poise навязывает репозиториям, разрабатываемым с его помощью.

## Путь проверяемой копии

Операция перечисления получает конкретный filesystem path checkout AI poise. Этот путь используется только для разрешения объявленных `source`, `tests` и `fixtures`. Расположение каталога пакетов и обычное разрешение исполняемого кода/configuration Poise от него не меняются.

Каждая декларация содержит владельца и явные integration boundaries. Пакет выбирает набор проверяемых файлов; команды выполнения остаются у зарегистрированного runner и не дублируются в каталоге пакетов.

## Членство

Каталог использует три категории:

- `source` — производственный, runner и helper-код, поведение или байты которого влияют на пакет;
- `tests` — pytest targets, которые непосредственно запускаются для пакета;
- `fixtures` — неисполняемые конфигурационные, документационные и data-входы тестов, включая `conftest.py` и builders по их назначению.

Отдельной категории `support` нет. Входы, ранее помещённые туда, распределяются между
`source` и `fixtures`; это исключает четвёртый путь перечисления и хэширования.

Пути — repository-relative POSIX patterns. Пустое совпадение является ошибкой конфигурации, чтобы устаревшая декларация не превращалась в молчаливое отсутствие проверки.

## Кэш пакета

Кэш этих пакетов принадлежит **кодовой базе AI poise**, а не общему runtime Poise. Реализация описана в [разделе «Идентичность кэша»](test-package-cache.md#идентичность-кэша).


## Хеширование и исключительное владение

Имя файла/пакета не доказывает неизменность его содержимого. Для всех разрешённых
исходников, тестов и фикстур требуются раздельно учтённые SHA-256 полных байтов.
Четвёртой группы нет. Описание текущего формата и контракта приведено в
[контракте ключа](test-package-cache.md#состав-целевого-ключа-и-сохраняемого-манифеста).
Каталог обязан охватывать фактические зависимости: файл вне membership не
участвует в хешировании, даже если тест импортирует его во время исполнения.

Общая запись кэша публикуется/заменяется только после
[захвата исключительного владения](test-package-cache.md#монопольная-запись-через-владение).
Это отдельное право на cache resource, а не следствие владения Task/worktree.
Требование не означает, что оно уже реализовано;
[статус контракта](test-package-cache.md#статус-выполнения-контракта) указывает пробелы.

Обычный запуск выполняется без редактирования его входов. Защита от намеренной
подмены агентом во время теста не требуется; см. [режим выполнения](test-package-cache.md#обычный-режим-выполнения-тестов).
Владение должно поддерживать автоматическое освобождение после смерти процесса и
[операторское восстановление после зависания](test-package-cache.md#смерть-или-зависание-владельца)
без перезагрузки и бессрочного ожидания.
