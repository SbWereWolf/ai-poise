# Context and handoff

Use [ready-result handoff](../../docs/workflows/batch-work.md#передача-результата-одной-командой),
the [ordinary release packet](../../docs/workflows/local-handoff.md#пакет) for incomplete materials, and
[direct role handoff](../../docs/workflows/local-handoff.md#прямая-передача-между-исполнителем-и-проверяющим).
A conversation summary is not storage, release, acquisition or acceptance.

## Required context

Preserve project/Task, current stage/role, exact source/result identity, actual allowed paths,
requirements, findings/resolutions, full check/evidence links, blockers and next authorized action.
Include the stable progression request/target, omitting the target when that is the actual intent.
Link authoritative current sources instead of copying whole specifications.

## Transfer

For a ready stage result, submit public handoff with the complete current result template,
original artifact intents, task_id, stable request_id and reason. Omit target_stage for
maximum progression or name the intended entry stage. Read the full verification,
progression and release outcomes; retain the actual progression identity for the receiver.
For incomplete materials, preserve them through existing owners before separate ordinary
release; use its actual Task version and task_id/request_id/expected_version/reason.
Release alone neither submits nor verifies a result. Confirm actual ownership release before
messaging the known counterpart. The recipient acquires the same Task through its own
bootstrap and continues in the existing working area with preserved WIP; no archive,
transport or bundle is created. Existing authorization covers ordinary continuation,
not unrelated work, Task acceptance or controlled publication/integration.

Known pre-effect refusal leaves ownership with the sender. A blocked response or release:null
does not prove retained ownership after a lost release acknowledgement. Establish the real
owner/original receipt and retry the exact original handoff; preserve an acquired receiver
claim, without a blind new release or reacquisition. Unknown external checks keep their
existing recovery gates. A message cannot repair an unconfirmed outcome. After successful
release, retry failed notification against the same saved result without silently reclaiming work.
Do not impersonate a reviewer or caller. Preserve incomplete material and actual unknown outcomes.

## Resume

Use the same authoritative Task state and source/evidence identity. Inspect actual gates and pending
effects before continuing. Do not merge stores, reconstruct a second lifecycle, copy another
participant's work area or edit managed state. The restored handoff composition does not
restore removed transfer/scoped transport services. Scope and authority remain with the
current public owners.
