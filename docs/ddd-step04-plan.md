# HARNESS-DDD-04 — наблюдения и доказательства

Создано: 2026-09-06T18:43:58+05:00.

Цель: общий observe/check на существующем runner, точные командные наблюдения и некомандные аргументы, продолжение одного этапа без повторного запуска уже завершённой команды, отдельное принятие/отклонение аргумента осмотром. Не вводить отдельный движок на цель.

Границы: новый явный evidence_plan каждой задачи, evidence_work в едином результате этапа, Task владеет записями, чистые VerificationPlan/EvidenceBook, SQL через общий UoW. Старый store/config не мигрируется. Артефакты только путями. Command result (факт) отдельно от predicate verdict и процесса: отрицательный subject check не является сбоем Harness, timeout/неизвестный исход не являются доказательством отрицания критерия.

Набор этапов: tests → RED → осмотр tests → реализация → GREEN → осмотр/исправления → docs → полный и changes архивы.

Обязательные маршруты: command observe; command check с отрицательным предметным результатом; logical-only PREPARE; command→CONTINUE logical argument; read-only inspect принимает/отклоняет конкретную revision; обратный переход и новое предложение; корректная изоляция task и неизменность истории. Повтор без изменения состояния не повторяет наблюдение; изменение дерева/команды/явной среды делает старое наблюдение неприменимым. Отказ предмета не ослабляет проектные guard checks.

Критерии: прежние тесты сохранены после явного обновления fixtures к новому формату, новые domain/application/CLI тесты, настоящий локальный Git/SQLite/subprocess smoke, rollback, архитектурные проверки чистоты, документы и архив. Нет обещания полной поддержки 13 нормативных конфигов, автоматического recovery внешнего unknown outcome или оценки истинности логического аргумента.
