## Проверенная область
Чистые HookDefinition/ProbeSpec, batch commands, FileHookRepository/HookRegistry, session binding и launcher, common WorkTools вызов, bounded stdio probe, CLI envelope, новый setup и пример. Домен не выполняет I/O. Registry не изменяет Task/Sprint напрямую. Inventory не выдаётся за probe.

## Обнаружено и исправлено
1. Installer считал digest JSON до round-trip через canonical SQLite serialization, из-за чего повтор после записи hooks считался изменённым. Теперь hash и фактическая публикация используют одно sort_keys представление. Регрессия replay/edit проверена.
2. В definition допускался явно некорректный matcher `[`. Теперь синтаксический отказ до записи hooks; native диалекты за пределами поддержанного literal/regexp набора не объявляются совместимыми автоматически.
3. UserPromptSubmit без обязательного prompt мог создать событие расхода. Теперь проверяется наличие строки; тело не сохраняется. Turn id обязателен, не выдумывается.
4. Taskless read-only bootstrap возвращал capability failure при отсутствующей IDE. Теперь диагностические результаты видны, но отсутствие IDE не блокирует сводку без активной задачи. Активная работа остаётся под gate.
5. Начальный settings требовал ручного файла. Добавлен runtime-setup: полный явный settings + установка + probes в одном пакете. Недостаточные поля не получают defaults.

## Проверка чувствительности тестов
Три мутации в одноразовых копиях: сохранение старых managed hook groups при edit, обход project assertion, новый message ID на каждый повтор одного native turn. Итоговые три копии отклонены тестами. Исходники не изменены.

Первый mutation-запуск сам имел два ограничения: детектор искал буквальное слово AssertionError вместо фактического assert-failure; выбранный узкий тест повтора сообщений до выбора задачи не выявлял мутацию приписывания активной задаче. Сохранён исходный результат; для последнего дефекта применён существующий сквозной тест generated hooks, где повтор происходит и при активной задаче. Новые критерии не подменяют реальное падение тестов.

## Сохранённые границы
Живой Codex/IDE отсутствует в проверяемом окружении. Тестовый MCP subprocess — протокольный стенд, не JetBrains. Root hooks не являются универсальной subagent identity. Нативные hooks не полная enforcement boundary, Stop не выполняет acceptance, SessionEnd не заменяет handoff. Read-only smoke по объявлению не доказывает безопасность произвольного стороннего исполняемого файла: команды задаёт доверенный конфиг проекта.

Внешние Git/CLI/IDE операции с неоднозначным исходом не решаются автоматической повторной установкой программ. Probe имеет ограниченные timeout/output/pages/messages и возвращает инструкции. Полнота сообщений partial. Метрик токенов и оплаты здесь нет.
