# Bounded document intake

Read only when changing or diagnosing document-read classification, configured
budgets, the common dispatcher or their boundary tests. Canonical owners are
[project file reading](../../../../docs/configuration/project-file-reading.md),
[file-intake lifecycle](../../../../docs/workflows/file-intake-lifecycle.md) and
the [source reader](../../../../docs/workflows/source-reader.md).

Discover paths/headings/matches before selecting exact files and finite ranges.
Use the selected installation's supported reader and explicit policy. Do not
concatenate large document sets, bypass a protective denial with another shell,
or treat a clipped response as delivered complete source. Distinguish missing
configuration, unsupported command shape, unsafe scope and an exceeded budget.

Keep admission, execution, full capture and model-facing presentation at their
existing owners. Poise uses one configured entry per host event and ordered
middleware; do not copy independent concurrent ERP PostToolUse hooks. Full data
consumed by another tool remains complete; the common output owner controls
agent display. No new per-tool clipping or alternative reader ledger belongs here.

Reuse the real producer/consumer tests and configured limits. A documentation link
or parser test alone does not prove live delivery. Record actual input, boundary,
decision and coverage in current evidence.
