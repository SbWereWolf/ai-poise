# ERP-MIG-F3-06-C017

Обновлено: 2026-09-16.

Реализован impact selection через существующие AiPoiseTestPackages и DevelopmentRouting.

Проверяются source/tests/support/fixtures, новые/удалённые файлы и переименования как пара путей. Прямые владельцы дополнены только явно объявленными интеграционными границами одного шага. Каждое решение содержит файл, owner, категорию, pattern и причину добавления соседнего пакета. Неизвестный input внутри известного src/** теперь даёт needs_inputs, а не незаметный пропуск.

Обязательные методы Task сохраняются. Результат может быть передан прежнему package-cache/RegisteredCheckRunner: реальный тест запускает только выбранный пакет, оставляя намеренно падающий посторонний тест незапущенным. Router сам не выполняет проверки. Папка — только explicit AI-poise subject; executable/config resolution не меняется.

TDD: до реализации 16 тестов impact и 3 route-теста воспроизвели отсутствие поведения. Итоговая группа impact/router/catalog/cache/DDD: **47 passed**, bounded smoke: **6 passed**, проверка ссылок и git diff --check пройдены. Логи и JUnit включены в checkpoint.

Полнота mapping не выводится из расширения src/**: незарегистрированные пути остаются явными gaps. Нет универсального кэша/анализатора чужих проектов, рекурсивного test discovery или автоматической сдачи результата.

Состав и зависимости: [актуальный F3](../f3-execution-plan.md). Task DB/lifecycle не изменены. Самопроверка не является независимым ревью.
