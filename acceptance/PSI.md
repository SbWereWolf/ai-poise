# ПСИ AI Poise: приёмо-сдаточные испытания

Реализация: [`psi/cases.py`](psi/cases.py), общая техническая механика:
[`psi/support.py`](psi/support.py). Условия и порядок выполнения задаёт
[ПМИ](PMI.md), а не этот набор сценариев.

Каждый сценарий независимо создаёт исходную среду через публичные интерфейсы.
Poise устанавливается из wheels; `PYTHONPATH` и переменные прежних сессий
не наследуются. Прямых изменений операционной SQLite нет. SQLite читается
только как независимая проверка наблюдаемых данных. Повреждение файла допускается
лишь как явно объявленный отрицательный вход в одноразовой испытательной среде.

| ID | Arrange | Act | Assert |
|---|---|---|---|
| PSI-01 | Новый Git-репозиторий, профиль, отсутствующая runtime DB | check, infra/deps dry-run, deps → infra → check, повтор | Dry-run не создаёт state; три БД созданы владельцами; повтор сохраняет bytes/modes |
| PSI-02 | Новая установка; её Task DB намеренно повреждена | check и infra | Ошибка и рекомендация; файл и прочие данные не заменены |
| PSI-03 | Новая установка; Task DB получает права 0000 | check обычным UID | Отказ permissions; права не расширены; после возврата исходных прав bytes совпадают |
| PSI-04 | Профиль с исходным путём state | Все три команды с --set state_root | Используется только новый путь; старый контекст не выдаёт ready |
| PSI-05 | Новая установка без Task | taskless bootstrap → verify | Нет Task/worktree; исходники неизменны; read_only_verified |
| PSI-06 | Новые требования и standalone Task с проверкой содержимого файла | create → ready → bootstrap → produce → verify → accept → integrate | Работа в отдельном worktree, точный результат в main, задача принята, повтор integrate идемпотентен |
| PSI-07 | Новый Sprint A → B; B действительно проверяет файл A | Попытка B до A; выполнение/интеграция A; затем B | Ранний B блокирован; результат A доступен в worktree B; оба результата в main |
| PSI-08 | Принятый результат Task и независимое продвижение основной ветки | integrate; повтор того же intent | Сохранились оба результата и accepted commit; merge подготовлен в task worktree; повтор не меняет HEAD |
| PSI-09 | Активная Task со staged WIP | restart → ready → bootstrap → завершение | Staged WIP не пропал, путь worktree сохранён, результат завершён |
| PSI-10 | Task производит неверное содержимое | verify FAIL; попытка accept; исправление; verify PASS → accept → integrate | Ошибка не стала completion; main не изменился до успешной приёмки; исправленный результат опубликован |
| PSI-11 | Незавершённая Task после выхода всех её CLI-процессов | Другой реальный процесс; отказ обычного захвата; recovery_template → after_crash → bootstrap | WIP сохранён, владение восстановлено явно, результат завершён без имитации SessionEnd |
| PSI-12 | Активная Task с незакоммиченными файлами | cancel → terminal inspection → next | cancelled не runnable; main не изменён; незавершённые файлы не уничтожены |

## Что не подменяется испытаниями

Одноагентная проверка не называется независимым ревью. PSI-11 моделирует
прерывание между завершёнными публичными командами; произвольное убийство
процесса посреди транзакции, отключение питания и отказ диска этим сценарием
не доказаны. PSI-08 покрывает бесконфликтное продвижение target и replay;
конфликтный merge имеет отдельные адресные тесты продукта.

Отмена не даёт разрешения уничтожать уникальные незавершённые файлы, поэтому
PSI-12 проверяет их сохранение, а не требует безусловного удаления worktree.
Различаются готовность инфраструктуры, успешная проверка поведения и перенос
установки на внешний сервер.
