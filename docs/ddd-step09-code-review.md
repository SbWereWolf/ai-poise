# Осмотр кода и исправлений DDD-09

Обновлено: **2026-09-07T07:39:59+05:00**. Это self-review, не независимый peer review.

## Границы

CatalogueCommands использует существующий редактор, не пишет JSON/SQL напрямую.
TaskBlueprint вызывает единый creation validator; не содержит названий целей.
PlanningPublications использует Task/Sprint/ActionRun и UoW, публикация source section
не принимает заменяющий inline draft и проверяет, что section не writable на publish.
Ни один новый handler не присваивает жизненный цикл и не выполняет внешнюю команду.
External I/O остаётся в infra; DB transaction атомарна только для своих строк/receipt.

## Найденные и исправленные проблемы

1. После return к сбору/анализу обычные handlers не могли принять correction proposal.
   Добавлен общий явный пакет resolutions; принятие остаётся у следующего inspect.
2. Catalogue предварительно проверял process candidates, но не все формы запросов.
   Плохой второй expected_revision/request_id мог оставить первый конфиг опубликованным.
   Проверка формы вынесена из одиночного редактора в общий validate_batch_request,
   используемый обоими путями до первого файла. Регрессии сначала дали два отказа.
3. Повторный inspect в walkthrough не подавал отдельное решение по аргументу, если прежний
   inspector уже принимал эту версию. Сценарий исправлен: текущий осмотр имеет собственное
   решение. Библиотечное требование не ослаблялось.
4. В diagnostics framing поле известных фактов было оставлено шаблонным. Fixture теперь
   передаёт исходные наблюдаемые условия до отдельного воспроизведения; будущий receipt
   не выдумывается.
5. Новый publication API изначально читал несуществующее stage.sections вместо stage.rules;
   исправлено по реальному интеграционному тесту.
6. Assertion демонстрации ожидал scope в краткой artifact-ссылке, хотя API возвращает id/path.
   Исправлен потребитель; проверяется существование каждой реально возвращённой ссылки.

## Отрицательные пробы

В трёх одноразовых корректных копиях отключались preflight поздних items, проверка
ссылки метода при создании и запись feedback proposal. Все три ожидаемо отклонены тестами.
Первичная подготовка мутаций по ошибке исключила каталог modules/evidence и дала collection
errors (exit 4); это не считается обнаружением дефектов. Сохранено отдельно; копирование
исправлено, отрицательные пробы повторены со синтаксически корректным кодом (exit 1).
