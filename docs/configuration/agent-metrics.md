# Запись телеметрии агента

## Назначение

Встроенный обработчик `agent-metrics` записывает доступные наблюдения обычной
работы агента: использование инструментов, токенов и контекста, время и сведения
об источнике. Значения сохраняются вместе с единицами измерения, доступностью,
идентификаторами проекта и сессии. Связь с задачей и спринтом записывается при
наличии подключённого владельца; для общей сессии она не требуется.

Неизвестное значение отличается от измеренного нуля. Повторное чтение того же
наблюдения сохраняет его идентичность; два самостоятельных вызова инструмента
остаются двумя вызовами. Неполные данные и конфликты источников видны при чтении.
Сохраняются извлечённые наблюдения, а не архив исходных переписок.

Классификация назначения вызовов, оценка эффективности, exposure, сравнение
истории и аналитические отчёты относятся к внешней обработке сохранённых данных.
Механизм записи их не вычисляет. Уже предоставленные источником показатели
сохраняются с их происхождением; отсутствие показателя не заменяется оценкой.

## Настройка

[Пример политики](../../config/examples/agent-metrics-policy.example.json) и
[пример обработчика](../../config/examples/agent-metrics-handler.example.json)
содержат демонстрационные пути. Скопируйте их во внешнюю конфигурацию установки,
задайте свои абсолютные пути и подключите обработчик к нужным маршрутам через
существующего [владельца runtime hooks](runtime-hooks.md).
Эти примеры сами по себе ничего не устанавливают и не меняют рабочие настройки.

Политика `poise-agent-metrics-policy-1` содержит:

| Поле | Содержание |
| --- | --- |
| `root` | Абсолютная папка данных телеметрии |
| `accounting` | Часовой пояс, границы событий/файлов/данных, источники, категории путей, токенизатор и имена SQLite/lock |
| `delivery.directory` | Папка очереди относительно `root` |
| `delivery.policy` | Границы очереди, размера события, попыток, размера пакета и времени повтора/блокировки |
| `collection` | Границы ожидающих захватов, размера источника, размера порции чтения и список источников |
| `retention.mode` | `keep`: сохранённые записи сохраняются |

Каждый источник имеет уникальный `id`, `kind`, `parser_version` и непустой список
абсолютных `paths`. Поддержаны `codex-native`/`1`,
`codex-transcript`/`invocations-2.5`, `hook-adoption`/`1` и `skill-policy`/`1`.
Последний записывает предоставленные снимки политики, без аудита содержимого навыков.
`max_records` задаёт размер порции: чтение продолжается до зафиксированной границы,
а незавершённая последняя строка остаётся неполным хвостом. `max_source_bytes`
ограничивает допускаемый размер источника, а не обрезает его незаметно.

В примере токенизатор явно недоступен. Это не мешает сохранять счётчики токенов,
которые предоставил сам источник. Все числовые границы примера являются настройкой
примера, а не рекомендацией для любой установки. Блок `analyses` не требуется.

## Чтение и повторная доставка

Используйте Python установленной поставки и абсолютные пути выбранного проекта:

```bash
"$poise_python" -I -B -m poise telemetry \
  --config "$project_json" --checkout "$checkout" \
  --policy "$metrics_policy" --audience machine < "$request_json"
```

Пример JSON запроса записанных фактов сессии:

```json
{
  "schema": "poise-agent-metrics-request-1",
  "operation": "query",
  "scope": {"kind": "session", "id": "00000000-0000-4000-8000-000000000161"},
  "period": {"from": null, "to": null},
  "view": {"kind": "facts", "family": null}
}
```

Замените UUID на идентификатор своей сессии. `family: null` выбирает все записанные
семейства. Границы периода — ISO timestamps с часовым поясом либо `null`;
нижняя граница включена, верхняя исключена. Запрос читает сохранённые факты,
сохраняя их происхождение и сведения о покрытии источников.

Для диагностики доставки используйте `operation: "status"`, для повтора ожидающей
доставки — `operation: "replay"`. Оба запроса содержат только `schema`, `operation`
и `scope: {"kind": "project", "id": "<идентификатор выбранного проекта>"}`.
Состояние доставки и покрытие выбранных источников не доказывают полноту всей
истории агента. Повторная доставка использует существующую очередь и идентичности
наблюдений, а не повторяет основную работу инструмента.

`--audience machine` сохраняет полный JSON для программного потребителя;
`--audience agent` использует существующее ограниченное представление и файл
полного ответа по [общему договору вывода](../workflows/runner.md#три-представления-вывода).
Запрос к отсутствующей истории возвращает `unavailable`, а не создаёт фиктивную
успешную запись. `rejected` и `unavailable` дают exit 2; неполный `replay` — exit 1.

## Сбои и сохранность

Захват и доставка используют отдельную очередь и существующего получателя
телеметрии. Ошибка источника или получателя сохраняется в диагностике; результат
основного инструмента сохраняется. При отказе изучите `status`, причину и
`continuation`, устраните указанную причину и повторите доставку через `replay`.
Не удаляйте очередь или историю для устранения отказа и не заменяйте неизвестные
показатели нулями. Настройки и данные установки остаются вне исходного Git-дерева.
