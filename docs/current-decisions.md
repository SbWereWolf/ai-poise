# Текущие решения разработки

Обновлено: **2026-09-06T20:44:16+05:00**.

Последняя исполняемая поставка — DDD-04A: пакетный редактор goal-type конфигов. Текущее уточнение затрагивает только документы, план и описательные приёмочные случаи; исходный код, исполняемые конфиги и тесты DDD-04A не изменены.

DDD, один runner и общие библиотеки сохраняются. Task владеет содержательными изменениями и переходами; механика проверки/сохранения вынесена в сервисы. Graph задаётся явно, inspect не исправляет предмет, revise не принимает себя. Evidence/аргумент/решение осмотра различаются.

**DDD-04A** реализовал редактор конфигов; следующий **DDD-04B** добавляет прямой декларативный batch-вход Task, генерацию артефактов и запись пользовательских событий. Агент передаёт желаемые изменения объектов одним пакетом, а не патчи process JSON, SQL и операции файлового учёта. Конфиги генерируются/изменяются инструментом; артефакты создаются из явного шаблона либо содержания. Регистрация существующего артефакта остаётся path-only. Исходники/тесты/документация целевого продукта продолжают редактироваться нативными coding tools.

Шаблон применяется явно с закреплённой revision. Missing required значения не берутся из fallback. Независимые process packs материализуются отдельно; snapshots задач и существующие DB не мигрируются от изменения конфига.

Добавлена независимая метрика пользовательских сообщений по задаче и агрегатам. Не оценивает tokens, не равна tool calls. Первичная запись — DDD-04B, runtime capture — DDD-07, агрегаты — DDD-08; источник и полнота явные.

Пользователь подтвердил: в отчёте рядом со счётчиком обязательны тип цели, число содержательных этапов и предъявленных итераций. Обычная приёмка/«дальше» не считаются дефектами; изменение требований отделяется от исправления прежнего результата. Причина сообщения и связь с предъявленным результатом учитываются только когда известны; неизвестные остаются неклассифицированными, не исчезают и не получают вымышленную причину. Счётчик сообщений не равен числу находок. Сбор этих данных не требует дополнительного инструментального вызова.

Это подтверждение относится именно к указанной метрике; оно не классифицирует автоматически остальные пункты списка кандидатов в правила.
