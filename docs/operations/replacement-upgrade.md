# Замена прежней установки на AI poise

Это замена пакета, а не совместимое обновление. Старое пространство имён и
исполняемая команда после операции отсутствуют.

Соберите wheel `ai-poise`, затем выполните единственный поддерживаемый сценарий:

```bash
python tools/upgrade_to_ai_poise.py \
  --python /путь/к/целевому/python \
  --wheel /путь/к/ai_poise-0.16.1-py3-none-any.whl
```

Сценарий последовательно выполняет
`pip uninstall -y agent-harness-happy-path` и устанавливает переданный wheel
`ai-poise` без обращения к индексу пакетов. После замены проверьте:

```bash
/путь/к/целевому/poise --help
```

Команда `harness` и импорт `harness` после замены намеренно не поддерживаются.

## Граница регрессионного аудита переименования

Проверка `tests/delivery/test_poise_namespace.py` читает поставляемые исходники,
тесты, инструменты, конфигурацию, skills и документацию, в том числе новые файлы
до коммита. Mutable Task-материалы в `projects/`, история Git, журналы передачи
и recovery manifest не являются действующими пространствами имён продукта.
Они сохраняются в полном архиве, но не проверяются как установленный код.

В Python проверяются имена импортов и публичных объектов, переменные окружения,
статически заданные динамические импорты и команды в стандартных вызовах
запуска процессов. Строка отрицательной миграционной фикстуры или неизменяемый
Task/installation ID не становится исполняемой командой только из-за упоминания
старого имени. Обычный термин harness не является старым именем пакета.
В документации и конфигурации проверяются команды и явные entry points.
Точные неисполняемые исключения истории и процедуры замены остаются в
`config/legacy-namespace-allowlist.json`; исключать целиком executable surfaces нельзя.

Это ограниченная статическая регрессия, а не доказательство свойств произвольного
динамически построенного Python-кода. Работоспособность установки и отсутствие
совместимых runtime-алиасов проверяются дополнительно исполняемыми тестами.
