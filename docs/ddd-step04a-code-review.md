# Осмотр кода и исправлений DDD-04A

Обновлено: **2026-09-06T20:26:43+05:00**. Self-review автора; независимый reviewer не участвовал.

## Проверенные границы
- Pure `GoalTypeDefinition` отвечает за декларативный кандидат, не за I/O.
- `GoalConfigCommands` работает через ports; CLI не обходится raw JSON Patch.
- `load_config` и редактор используют один полный валидатор process.
- Lock извлечён из SQLite adapter в общий инфраструктурный примитив.
- Файловая публикация не изображается частью SQLite-транзакции.
- Изменение pack не переписывает snapshot активной задачи; actual project execution config всё ещё защищён.
- Новые template/limits/paths явно поставлены в конфиге; numeric values тестов не объявляются нормативными для всех проектов.

## Конкретные воспроизведённые проблемы
1. Исходный `_task` сравнивал hash всех актуальных process-файлов, поэтому редактирование pack блокировало существующую задачу. Тест `test_existing_task_keeps_snapshot_and_new_task_gets_new_pack` сначала падал, теперь проверяет старую и новую задачи и реальный RED старой задачи.
2. Первая версия CLI могла опубликовать конфиг, а затем не суметь выдать даже указатель результата при output_chars=1. Тест подтвердил публикацию; теперь settings отклоняют невозможную ёмкость до business operation.
3. При pending publication изменение target path в settings могло направить прежний кандидат в новый файл. Тест сначала воспроизвёл это; recovery и replay теперь проверяют зафиксированное назначение.

Также проверены conflict/no-op/history replay, атомарный отказ невалидного пакета, ошибки до и после replace, внешний diff, неизвестная schema, symlink-escape и 240 связанных изменений одним пакетом. Для поиска пересекающихся свойств используется индекс по объекту, не попарный обход всех изменений.

## Отрицательные проверки
В отдельных копиях намеренно отключены expected revision, защита от конкурирующих patch одного свойства, проверка назначения pending и фиксация Task snapshot. Соответствующие поведенческие тесты все обнаружили внесённые ошибки. Это не общий mutation score всей системы.

## Границы
Редактор обслуживает один зарегистрированный target за запрос. Команды и EvidencePlan конкретной задачи остаются в Task-контракте. Agent-first batch verify/ArtifactFactory/message events — DDD-04B. Продуктовые 13 процессов целиком не объявлены реализованными. Примеры reviewer decisions являются fixtures.
