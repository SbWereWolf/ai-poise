# HARNESS-PILOT-01 — практическая подготовка проекта

Начато: **2026-09-07T13:50:37+05:00**. Обновлено: **2026-09-07T14:15:55+05:00**.

Цель — замкнуть отсутствовавший вход реального проекта без ручной сборки конфигов.
Объект применения — существующие исходники Harness; чужая codebase и endpoints не предоставлены.

Требования: один пакет создаёт независимый полный project definition; вопросы и типы анкеты
задаются выбранным шаблоном; back/change/keep/abort; явная публикация; общий runtime validator;
никаких defaults, SQL, Task/worktree или изменений приложения на этапе подготовки.

DoD: созданный проект принимает обычный bootstrap; проверяется 13 процессов; повтор не
дублирует и не стирает данные; неверный кандидат не публикуется; repository readiness не
выдаётся за сеть; read-only реальный пилот останавливается verified без самостоятельной
приёмки; существующие regression tests выполняются и их реальные исходы сообщаются.

TDD: контрактные tests первыми; их RED означает отсутствие нового API, а не тестовую
регрессию продукта. Затем GREEN, осмотр, воспроизведение конкретных дефектов, исправления,
документация и отдельный архив. Никакие migration или schema upgrade Task DB не выполняются.
