# Осмотр кода и исправлений DDD-02

Обновлено: 2026-09-06T17:36:12+05:00.

Осмотр выполняет тот же агент. Не является независимым peer review.

## Найдено и исправлено
1. После первоначальной реализации round-trip policy из SQLite менял порядок полей record и нарушал равенство snapshot. Поля record канонизированы; порядок точек маршрута при этом сохраняется.
2. Новый content gate возвращал structured failure, но старый CLI считал неизвестный status успешным. Написан падающий CLI regression; content_requirements_failed теперь exit 1. Не смешивается с test verdict либо Harness Incident.
3. Первая версия позволяла ссылаться только на методы создания task. Добавлены неизменный CheckRegistry и method_additions в тот же submission; тест реально исполняет новый метод. Нет отдельной обязательной команды регистрации.
4. Без coverage можно было определить только одну цепочку из нужных двух и не иметь общего минимума охвата. Добавлено явное coverage obligation типа цели, проверяющее task requirement IDs и configured minimum points.
5. Убран ненужный diff форматирования старых tests/demo: изменения публичной формы внесены адресно, сохранены комментарии и основная структура прежних тестов.
6. Удалено дублирование cardinality: старый path-only API и новый gate вызывают общий чистый счётчик. Registry использует один validator точной команды вместо копии в common.
7. Проверено атомарное сохранение contract/trace/method/sections. Реальный отказ SQL trigger не оставляет половину пакета. mark_verified не обходит требования даже при прямом вызове Task.

## Границы осмотра
Не исследовались вымышленные гонки двух агентов за одной task и cancel во время verify: их пользователь исключил. Не строился универсальный DSL валидаторов. Не расширялись scope automatic tests на конфиги/зависимости. Не возвращались смысловые декларации артефактов.

Не претендуем на полное recovery и на доказательство правильности текстового аргумента. Одной записи reference/state=documented недостаточно для фактической проверки файла: это явно описано в контракте.
