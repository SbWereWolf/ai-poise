# Самопроверка DDD-07

Обновлено: **2026-09-07T00:10:42+05:00**. Проверял тот же агент; независимого review не было. Пользовательские инструкции и решения осмотра в примерах — fixtures, а не выводы другой модели.

## Предмет
Runtime identity/cursor, представления команд, local handoff/release/resume, сохранность Task/Sprint и нового источника метрики. Прежние библиотеки не заменяются. Не рассматривалась защита от злонамеренного произвольного редактирования самой БД, два агента на одну задачу или cancel в середине verify — эти сценарии не входили в согласованную модель.

## Найденные и исправленные дефекты
| № | Проблема | Проверка и исправление |
|---|---|---|
| 1 | Parser Incident попадал только в текущий ответ, но исчезал при replay verified report | Регрессия падения worker; Incidents сохраняются в отчёте до Task.mark_verified |
| 2 | null-result handoff не продвигал runtime paths уже зарегистрированной submission | Регрессия сохраняет submission с runtime-файлом; adapter получает текущий кандидат и перепривязывает сохранённые пути |
| 3 | Отказ каталога views мог прервать сохранение фактического результата теста | Инъекция mkdir error; raw receipt/evidence сохранены, Incident отдельный, manifest=null вместо ложной ссылки |
| 4 | Чтение диапазона full-файла вызывало read_text всего файла | Регрессия запрещает read_text на full; streaming range и отдельно потоковый digest |
| 5 | Sprint продолжал считать released task занятой предыдущим агентом | Реальный handoff/resume через Sprint bootstrap; Repository отдаёт подтверждённый handoff, домен определяет resumable, базовое дерево не меняется |

RED этих регрессий сохранён: `review-regression-red`, `review-storage-red`, `review-sprint-red`. Итоговый полный набор проходит. В ходе изменения явной сигнатуры Sprint.overview один прежний test fixture был обновлён после TypeError; это ошибка адаптации теста, не функциональный PASS.

## Дополнительные проверки
Путь за roots/через symlink не принимается; полные потоки совпадают с receipt; неизвестный profile не угадывается; отсутствие требуемой capability блокирует запуск, а не создаёт доказательство доступности. Resume проверяет tree/branch/HEAD и bundle; неизвестное unclaimed состояние не усыновляется. Сбой SQLite release откатывает Task/receipt/session вместе, уже созданный WIP commit используется при продолжении.

Код чтения источника не сохраняет текст prompt. Из JSONL берутся только event_msg/user_message; response_item не дублируется. Счётчик не является billing и не сообщает full coverage. Парсер не выполняет project command повторно, worker не пишет Task.

## Отрицательные мутации
В отдельных копиях были удалены agent_id из identity, проверка raw digest и правильное распознавание user event. Соответствующие тесты упали по проверяемому поведению. Первая техническая попытка raw-мутации испортила определение функции (exit 4); она исключена из результата, затем применена валидная мутация только call sites (exit 1).

## Границы
Не проведены настоящая установка Codex hooks, IDE handshake, передача в Gmail или восстановление потерянного filesystem. После неожиданной гибели целого CLI нет полной durable очереди materializers: job/raw сохранены, но механизм автоматического восстановления фоновых jobs не заявляется готовым. Handoff одной task внутри одного store завершён; физический перенос store — следующий срез. Семь семейств handler не означают исполнение всех 13 нормативных процессов.
