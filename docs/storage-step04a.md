# Хранение DDD-04A

Обновлено: **2026-09-06T20:26:43+05:00**.

Task DB: версия 6. Табличная схема Task/Evidence не расширена редактором. Изменён контракт идентичности execution config: process snapshot принадлежит Task, не общей сумме hashes всех pack. Поэтому прежний store не читается; миграций нет.

Editor DB: версия 1 в явно заданном месте. Это отдельное инфраструктурное хранилище конфигурационного контекста, не обход Task UoW.

| Таблица | Назначение |
|---|---|
| `config_operations` | Уникальный request ID, digest запроса, goal ID, исходная revision, полный кандидат, receipt, pending/completed |
| `config_heads` | Последняя управляемая revision каждого pack |

Точные пути исходного/результирующего JSON находятся в editor settings/receipt. Version/digest выбранного шаблона сохранены в receipt; шаблон после создания не является живой зависимостью pack.

Один короткий `exclusive_lock` сериализует редакторские изменения; та же реализация примитива используется Task SQLite adapter. Команд приложений, Git/tests или ожидания пользователя под этим lock нет.

Файл записывается временно в каталоге назначения, синхронизируется и заменяется через `os.replace`. DB pending предваряет внешнее действие. Completion/head фиксируются одной SQL-транзакцией после наблюдаемого результата. Сбой до или после replace не превращается в обещание SQL-атомарности файла. Сохранившийся pending восстанавливается только при известных digest и прежнем назначении. Перенаправление target через изменённые settings блокируется.

Невалидный пакет может создать служебную пустую БД редактора, но не меняет активный process. Кандидаты ошибочных пакетов не становятся действующими. Детали отказа CLI автоматически сохраняет в configured responses root. Это пока не единый Task Incident/metrics ledger будущих срезов.

Повреждённые внешние файлы и неизвестные внешние изменения останавливают операцию. Универсальное автоматическое исправление произвольного damaged storage не заявляется.

## Первичные технические источники
Документация Python 3.13: [os.replace](https://docs.python.org/3.13/library/os.html#os.replace), [fcntl.flock](https://docs.python.org/3.13/library/fcntl.html#fcntl.flock), [sqlite3 transaction control](https://docs.python.org/3.13/library/sqlite3.html#transaction-control). Проверены в текущем срезе. Наличие atomic rename не означает общую транзакцию нескольких файлов и SQLite.
