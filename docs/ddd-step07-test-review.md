# Осмотр тестов DDD-07

Тесты сначала зафиксированы отдельно. RED — отсутствие новых модулей, не дефект приложения. Проверяются реальные файлы, процессы материализатора, Git/SQLite и повторное создание runtime. Синтетические Codex записи имеют один явно поддержанный формат `event_msg/user_message`, вторичные `response_item` не учитываются. Утверждение о полной поддержке live hooks из этого не следует.

Ключевые проверки: новый actor возобновляет незавершённую итерацию и видит сохранённый draft; ошибки/неизвестный pending не освобождают task; полный stdout сохраняется без усечения; ошибки представления не меняют командный verdict; snapshots capabilities — явно сообщённые, не выдуманное discovery.

Дальнейшая самопроверка должна включить injected DB failure release, полный путь через CLI, доступность stdout после cleanup, опасные пути и bounds источника сообщений. Не добавлять distributed claims или гонку cancel/verify, исключённые пользователем.
