# Ограниченное чтение исходников и документов

Обновлено: **2026-09-16**.

## Явные диапазоны и поколения контекста

`SourceReader` читает только переданные пути и включительные диапазоны строк (нумерация с 1).
`cwd` — конкретная папка для относительных аргументов этого чтения, не новый root Poise.
Абсолютный путь не переопределяется. Содержимое никогда не исполняется; инструменты и hooks
не загружаются из прочитанной рабочей копии. Допускаются обычные UTF-8 файлы, включая документы
вне папки Poise. FIFO, устройства, каталоги, двоичные/слишком большие файлы отклоняются.
Символическая ссылка разрешается в конкретный путь файла; он отражён в receipt.

Политика задаётся явно: `config/development/source-reader.json` содержит пределы количества
диапазонов, строк, размера исходного файла, суммарного возвращаемого текста, числа receipts
и ожидания блокировки. Это поставленная конфигурация, а не скрытые значения в коде.
Пакет проверяется целиком до записи receipts: ошибка одного диапазона не подтверждает остальные.
Отсутствующие строки не заменяются молчаливым усечением. Хэш относится ко всем байтам файла;
возвращаются только запрошенные строки. Файл, изменившийся во время чтения, отклоняется.

Для повторного чтения совпасть должны путь, SHA-256, диапазон **и поколение контекста**.
Дополнительно клиент явно передаёт `acknowledged` — IDs ранее полученных им receipts.
Сам факт записи/возврата текста не доказывает доставку клиенту или сохранённую память модели.
Без acknowledgement текст снова доступен. `unchanged` не содержит текст, но сообщает точную
идентичность подавленного повтора. `reread: true` с непустой `reason` всегда возвращает текст;
причина сохраняется в receipt. Условный справочник не становится обязательным к чтению.

`reset` с причиной `startup`, `resume`, `compact`, `clear` или `manual` и явным `event_id`
повышает поколение и удаляет возможность подавлять чтения по старым receipts. Повтор
**последнего** того же события идемпотентен. Старый номер поколения отклоняется.
После compaction/resume сначала выполняется reset, затем нужные тексты читаются заново:
неизменность файлов не означает сохранность контекста. Автоматическая связка с native hooks
описывается отдельно при поставке восстановления контекста C023.

Хранилище содержит только ограниченные метаданные чтения, без текста документов или копии
Task DB. Вытеснение старых receipts разрешает лишнее чтение, но не создаёт ложное `unchanged`.
Повреждённое состояние не сбрасывается незаметно. Файл состояния выделяется для одного
контекста клиента/сессии; разделять его между независимыми моделями нельзя.

## Прямой инструмент

В окружении установленного Poise, без bootstrap и Task mutations:

```sh
python /path/to/poise/tools/source_read.py \
  --policy /path/to/poise/config/development/source-reader.json \
  --state /path/to/session/reader.json
```

JSON на stdin:

```json
{"operation":"context","input":{}}
```

После получения поколения, например `1`:

```json
{"operation":"read","input":{"cwd":"/path/to/code","generation":1,"acknowledged":[],"reads":[{"path":"AGENTS.md","start":1,"end":10,"reread":false,"reason":""}]}}
```

После действительно полученного текста ID можно передать в следующем `acknowledged`.
Ответы — JSON, отказ имеет `status: rejected` и exit 2. Никакого глобального обхода файлов
или изменения разрешения путей инструмент не выполняет.
