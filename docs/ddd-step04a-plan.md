# HARNESS-DDD-04A — пакетный редактор процесса

Срез начат: 2026-09-06T19:53:43+05:00. Статус этого файла: план до реализации.

## Цель и границы
Один запрос создаёт полный независимый process pack из явно выбранного шаблона либо меняет действующий pack по ID. Агент не редактирует физический JSON. Один кандидат проверяется после применения всех связанных изменений. Публикуется только валидный результат. Текущие Task сохраняют собственный snapshot. Одна выбранная конфигурация за запрос; task/sprint и генератор artifacts — DDD-04B/05.

## DDD
`GoalTypeDefinition` владеет формой и пакетными изменениями. `GoalConfigCommands.apply_batch` выполняет один сценарий через порт. Файловый/SQLite adapter обеспечивает ожидаемую revision, operation receipts, атомарную замену одного JSON и восстановление известной недоставленной публикации. Общий валидатор используется редактором и runtime. Domain/Application не содержат I/O. Существующая блокировка извлекается в общий инфраструктурный компонент.

## TDD
До реализации сохранены domain/service/CLI/architecture tests. Начальный RED — отсутствие нового API, не ошибка среды и не доказательство прикладного дефекта. Дополнительно проверить активный Task snapshot после редактирования pack; новый Task получает новый контракт.

Сценарии: полный create; взаимосвязанные изменения в обратном порядке; 240 операций одним пакетом; конфликт изменения свойства; неизвестные ссылки и обязательные поля; отсутствие шаблона; optimistic revision; повтор и старый повтор после следующего изменения; failure до замены файла; отсутствие частичной публикации; bounded CLI со ссылкой на полный результат; изоляция соседнего pack.

## До выдачи
Осмотреть тесты и код; проверить common loader и старые регрессии; дополнить документацию API/границ/статуса; сохранить full и changes ZIP и Git bundle. Миграции и внешняя публикация Harness без remote не выполняются. Обработка неизвестных исходов не объявляется универсальным distributed recovery.
