# Осмотр тестов DDD-09

Обновлено: **2026-09-07T07:39:59+05:00**. Осмотр выполнял тот же агент.

Проверяются: независимые полные определения; типизированные параметры без неявного выбора;
один creation validator; 13 коротких и 13 feedback-проходов; отдельно 34 объявленных ребра;
read-only осмотр; реальный RED/GREEN, probe и merge; точная публикация сохранённого draft;
rollback детей и receipt; поздние ошибки batch до публикации; replay и детерминированные IDs.

Source templates и тестовые контракты записаны до реализации нового API. Начальный RED
в red.log — отсутствующий API, не воспроизведённая неисправность приложения.
feedback-red.log — реальные отказы обычных handlers принять предложение исправления.
Дополнительный catalogue-confirmed-red.log — два воспроизведения частичной публикации
первого конфига при заведомо невалидном позднем элементе.

При осмотре тестов исправлено ожидание полного равенства replay-ответа (его replay-флаг
намеренно меняется). Проверка удаления этапа теперь использует настоящий remove_stage,
а не ошибочную форму запроса. Проверка callback-переходов требует фактического посещения
именованного ребра и завершения той же задачи, не только наличия ID в конфиге.

User/reviewer/логические утверждения — сценарные fixtures. Их текст не доказывает качество
модели. Команды, Git, SQLite, путь начала опубликованной задачи реальны. SQL используется
только для аварийного trigger в отдельном тесте отката, не для переходов процесса.
